# Inspector 视觉迁移前的 Runtime 合同清单

状态：待处理。此表只收录会改变场景数据语义、运行结果或导出结果的事项；输入框排版、主题色、数值拖拽、页签切屏等纯 UI 工作不列入 Runtime。每一项先完成 Registry／数据合同、Inspector、Runtime、测试四个落点，再进入正式编辑器的视觉样式迁移。图鉴中的 `R01` 对应本表。

## R01 · 场景「扫描擦除」方向由四向变为连续角度

**现状**：`classic-v4-inspector-controller.js` 提供 `right / left / down / up` 四个选项；`runtime-src/vnext/80-scene-renderer.js` 用四种矩形裁切。设计图鉴中的环状方向盘尚不能直接写入正式项目。

**合同先决策**：0° 表示画面由左向右揭开；角度顺时针增加，90° 向下、180° 向左、270° 向上。项目文件使用 `directionAngle` 数值，归一化至 `[0,360)`；仍读取既有 `direction` 字符串，分别映射为 `0 / 180 / 90 / 270`。旧 `type:'scan'` 继续按向下扫描解释，但不在新保存文件中写出。新项目只写角度，不同时写两套方向字段。

**四层落点**：

1. Registry／场景协议：明确默认角度、合法范围、旧四向值的读取与重新保存规则；更新 `VNEXT_SCENE_CONTRACT.md` 和项目归一化入口。
2. Inspector：将四向下拉换为共享 `AngleField`，键入、方向盘、上下拖动均写相同数值；撤销／重做与时序段切换不改变角度。
3. Runtime：以前进法向量构造半平面裁切，对任意角度都在同一过渡时长内完整扫过画布；保留前后两个场景各自的动态时钟，不退化成静帧。预览、固定帧和测试导出调用同一实现。
4. 测试：旧四向项目兼容、0/45/90/135/180/270/359°、非方形画布、起点／中点／终点、动态前后场景、编辑器与测试页像素一致。特别检查斜向过渡没有未覆盖的角落或突然跳完。

**放行条件**：上述合同和测试通过后，才把图鉴的连续角度控件迁入正式 Inspector。只替换控件外观不算完成。

## 后续逐条登记规则

图鉴直接读取 13 张 Registry 效果卡，并由参数规划器按当前选择显示条件字段；效果动态只在所属效果启用、打开动态并展开参数后出现。Scene、组、元素、图元、图片／序列、粒子等手工编排区按照当前 Inspector 的显隐规则运行，Builtin 为 Manifest 输入协议示例，不假定所有模块都有相同字段。核对时若发现某输入交互要求新增或改变 Runtime 能力，新增独立的 `R02`、`R03` 等条目，写清四层落点和放行测试；不得以“顺手调整”为由混入 CSS／组件迁移补丁。

目前其余已知改动属于 Inspector 表示或编辑交互：0–100% 的用户侧透明度、宽高比例锁、数值上下拖动、滚动槽位和数显切屏，均不应改变项目存储值或 Runtime 计算。若实现中发现它们确实需要改 Runtime，应先更新此清单，再动正式编辑器。
