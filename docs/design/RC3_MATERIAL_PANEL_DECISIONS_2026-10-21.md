# RC3素材面板：项目／共享操作决议

状态：2026-10-21用户确认D2显式发布／更新方案；D3最新为标题下同一行左侧项目／共享二态按钮、右侧三个导入图标。归属[RC0～RC9计划](../architecture/V4_RESOURCE_PRODUCT_CONSOLIDATION_PLAN_2026-10-21.md)。RC3-a／b／c1／c2a及[c2b图样构件烘焙归位](../architecture/V4_RESOURCE_ENTRY_PLACEMENT_RC3C2B_2026-10-21.md)已实现；完整包归档／混合包及缺失提示等余项覆盖后才删除旧入口，不能把本批冒称完整RC5目录完成。

本轮意图为存量功能流程收口，沿用现有字体、色彩、侧栏和控件，不探索新主题。RC3-a沿此方向实现；实际截图与任务走查见RC3-a验收记录，未做独立视觉评审。

## 1. 用户任务与交付对象

用户把当前作品中的内容留下来，之后在同一作品或另一作品中再次使用，而不是理解资源类型、源码和依赖图。

产出例：名为“暖窗小屋”的元素素材，保存基础雨量88、循环动态、图片原图及Alpha修边、图样和受信实现依赖；不保存当前播放头的时序覆层。取用两次得到两个独立对象，改其中一个不改变素材定义、另一个对象或共享版本。

对象与动作沿用：素材先选后操作；结构树上的“收入素材库”只作用于选中普通／程序元素。元素不进入图片预处理；共享不是画布对象的实时联动。

## 2. 当前实现核对（源码证据，未做本轮浏览器走查）

| 现状 | 依据 | RC3处理 |
| --- | --- | --- |
| 图片素材与收藏为不同入口，收藏还混有Module／图样定义 | `classic-v4-resource-controller.js`的renderCurrent／registerShelf | 素材入口只呈现位图／序列／元素；图样和实现文件不单独冒充元素素材 |
| 收藏记录以完整资源包hash为键，列表没有稳定发布身份或更新关系 | `v4-resource-library.js`的put／list | 继续复用已校验包存储；增加显式发布关系，不能仅凭同名或resourcePins推断“已同步” |
| 当前收藏移除不改工程；有撤销移除 | 同controller的remove／restore | 保留不破坏工程的边界；确认及联动按D2／后续D4实现 |
| 元素预设数据闭环可用，但尚无入库面板入口 | RC2-a～c2b合同 | 新入口调用已有预设／资源API，不另建Runtime或捕获器 |

这些是源码核对，不冒称当前用户流程已验收；选定后须从实际入口重新记录操作与错误恢复。

## 3. D2推荐：显式发布、显式更新

| 操作／状态 | 推荐行为 |
| --- | --- |
| 项目素材首次打开“共享” | 发布当前素材定义的完整依赖包。成功后才亮；失败保持关闭，工程及选择不丢失 |
| 工程素材已经发布 | 开关只表示共享库仍有对应发布条目，不代表内容实时相同 |
| 修改画布中的实例 | 不使素材定义或共享条目变成“有更新”。两者是独立内容，不能自动回写 |
| 素材定义／位图预处理发生变化 | 保留已发布版本，选中操作区显示“更新共享”；发布成功后清除待更新状态 |
| 重新收入一个改过的画布对象 | 默认新素材；不凭名称覆盖旧定义。本轮不顺带增加“自动回写所有实例” |
| 点击“更新共享” | 更新同一发布条目的当前内容，其他工程已取用的副本不变；首版不提供版本历史界面 |
| 不同素材同名 | 两者保留，不覆盖；按冲突补短序号区分名称，实际身份不依赖名称 |
| 项目处关闭“共享”／共享处删除 | 同一个移除发布动作，确认后生效；不删除项目素材和画布实例，不碰同字节的其他独立发布条目 |
| 另一个工程保留旧发布关系 | 重新进入共享面板时核对库中实际条目；条目不存在则显示未共享，不凭旧resourcePins常亮 |
| 新工程从共享加入画布 | 先复制完整定义／依赖到项目，再建实例；完成后切到项目并选中对应素材。失败不留半份依赖 |
| 重复取用同一发布内容 | 项目已具备相同来源与内容则复用定义，画布仍新增独立实例；旧版本／修改后的本地定义不被新版本覆盖 |

共享库是显式持久化范围，不是自动恢复上次工程。程序包导入、静态卡片或悬停不能获得授信；仍按当前工程的信任流程执行。外部存储写入不伪装为Ctrl+Z工程历史，移除恢复和更新失败恢复需有明确结果。

**D2结论：用户确认以上显式发布／更新方案；首版不增加共享版本历史。**

## 4. D3推荐：两种范围，一套素材卡

- 在“素材／图样”标题下独立一行，左侧为项目／共享单按钮二态切换，显示当前范围文字及♡／♥，共享态高亮。它仅切换查看范围，不是选中素材的共享发布开关。旧收藏入口待剩余能力覆盖后再移除。
- 同行右侧用三个等规格线框图标呈现导入文件夹、导入精灵图、导入素材；均保留title、aria-label和原按钮id，不收进菜单。此为用户本轮对先前文字按钮布局的明确更新，不改导入业务。选中素材后才提供导出，删除／导出细则留RC4。
- 卡片显示处理后的缩略图、名称及位图／序列／元素标识。静止时显示素材定义时间0的首帧，非当前播放头。图片透明区域沿用棋盘预览。
- 单击选中卡片并显示操作；位图／序列同时沿用现有预处理入口。元素只显示加入画布、烘焙等相关动作，不进入位图预处理。
- 操作区只为当前选中卡出现，不要求hover才能找到。项目提供加入画布、共享和按类型的编辑／烘焙；共享提供加入画布及管理动作。删除／导出细节属于RC4，不先接一个错误语义的临时按钮。
- 首版单选，不增加没有批量动作支撑的多选框。保留键盘焦点，不因缩略图更新而重建／移动正在操作的按钮。
- 未悬停不持续渲染；仅鼠标所指或键盘明确请求的一张可见卡预览，离开即停止。序列先沿用2fps预览；元素以定义基础循环播放，受预览预算限制。禁止与主画布共享可变Player／授信状态。
- 未授信程序显示稳定占位及名称，不启动程序绘制；缺素材、实现缺失或加载失败显示对应状态，不悄悄使用第一张无关图或空白成功缩略图。
- 入库后切到项目，选中新素材且保持画布原选择；只加入库，不自动再放一个重叠对象。取用失败保留原选择和滚动位置。

单击进入预处理与单击只选择操作区之间，需要落实为同一条操作链：优先沿用现有位图单击编辑行为，不额外增加一次无目的确认；元素卡则只选择。不得把原用户提出的位图编辑入口无声改成必须双击。

**D3结论：标题下独立一行；左侧项目／共享二态开关，右侧三个导入图标常驻；其余卡片沿用用户已提出的单击与类型差异。**

### 本轮落点与验收

状态／Registry不改；UI由SharingController将原两范围Tab收为一个原生button，aria-pressed表示共享态，data-material-scope-current表示当前范围，data-material-scope仅表示点击将前往的范围。作用范围不再另占素材内容区一行。三个导入图标使用内联SVG，不增加图标库或字体下载；与范围开关在asset-import-actions同一行。Runtime／资源存储不改。

导入按钮自身会stopPropagation，因此范围复位直接绑定三个按钮，不能只依赖操作行冒泡；共享切项目／新建工程必须同步开关、内容隐藏状态和预览释放。按钮聚焦时空格保留原生激活，不触发画布播放；未聚焦按钮的空格快捷键保持原义。

项目素材浏览器夹具覆盖同排左右对齐、三个图标及可访问名、1024／1440宽度下操作行无溢出、空格／回车二态切换、各图标触发文件选择、切回项目及切工程复位。目录选择测试注入cancel事件，文件选择器设置空文件列表，不冒称原生OS取消窗口实测。共享发布及原快捷键回归通过；预览释放沿用定向回归。

技能截图工具证据位于tests/artifacts/rc3-material-toolbar-project与rc3-material-toolbar-shared，主Agent查看项目／共享两态。1440下操作行正常；1024下操作行不溢出，但整页既有最小宽度导致页面横向溢出（1208px），本轮不做整页响应式改造。临时服务器favicon.ico 404保留为已知非功能警告。仅做局部自检、无独立评分；替换了旧“右上＋”空状态提示，其余说明文字不变。

## 5. 建议实施批次与门禁

| 小批 | 四层落点与验收 | 边界 |
| --- | --- | --- |
| RC3-a 项目投影＋收入库 | 数据复用elementPresets／assets；结构树入库与统一项目卡；Runtime不改。实际入库、独立放置、预处理、撤销、存取工程 | 先不移除旧收藏入口 |
| RC3-b 共享发布状态 | 稳定发布关系＋内容hash；共享开关／更新／取用；复用库存储与资源闭包。跨工程、同名、旧版本、不继承授信、异步工程切换／存储失败验证 | 不引入自动更新实例或自动重开 |
| RC3-c 入口切换与预览 | 两范围一套卡、三类型静态缩略图与单个受控动态预览；覆盖旧图样／Module入口后再替换旧收藏入口 | 不能直接删去尚无归宿的旧图样操作；无重复写入 |
| RC4 生命周期与导出 | 再确认删除影响、共用依赖、共享移除恢复、可编辑包／烘焙导出 | 不能因RC3开发顺手默认连带删除画布对象 |

每批先固定Registry／状态、UI／命令、Runtime／Host、测试四层清单，再写代码。使用现有视觉与组件；验收同时包括实际交互、画面、工程读回、失败无半成品。这里只批准计划并不等于实际界面通过。

## 6. 已识别的衔接问题

1. 现有旧收藏混合图样和Module入口，不能在仅完成素材投影后直接移除整页；RC3-c必须给出能力迁移清单，未覆盖之前保留旧入口。
2. 项目定义修改与画布实例修改必须分辨；否则共享的“待更新”会再次成为难懂的隐式同步。
3. 共享记录按hash存储不等于发布关系：内容去重可复用，删除一条发布不应误删其他发布共用的字节。
4. 本地共享删除影响多个工程的发布状态，但已复制的实际内容不丢；禁止为更新亮灯而自动改写未打开工程文件。
5. 旧收藏数据要能读取；只能确定资源包内容，不能反推不存在的原始发布关系。首次迁移显示为独立共享条目，不猜测与某个同名项目素材自动绑定。
