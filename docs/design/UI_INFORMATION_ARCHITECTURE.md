# UI 信息架构

> 状态：首轮方向已确认。本文定义用户为了完成任务“先看什么、再做什么、何时展开什么”。

## 职责

定义工作流、页面工作区、信息层级、模式切换和渐进披露。它决定内容的结构与出现时机，不定义颜色、圆角或动画曲线。

## 当前待梳理范围

- 核心工作区：素材、画布、图层、局部 FX、时间轴、导出/保存/诊断；
- 全局模式：新建、图片建立、绘制、parts 编辑、蒙版编辑、粒子、局部 FX；
- 高频常驻项与低频二级项的划分；
- FX、蒙版、粒子等高参数模块的分组、折叠和默认展开策略；
- 新手路径与高级用户路径；
- 错误、空状态、加载/保存/导出状态的出现位置。

## 已确认的信息模型

产品不应把用户当作“填写参数的人”，而应让用户完成一次像素场景装配。首轮 UI 重构以四个稳定区域组织，不增加新的功能模式：

1. **创作空间（中心）**：画布、选择/绘制/蒙版等直接操作与即时预览。它始终是视觉主角。
2. **素材与构件（左侧）**：导入、处理、复用图片与生成构件；语义是“拿什么来做”。
3. **结构与时间（右侧 / 下方）**：图层、组、局部效果、可见时段和时间轴；语义是“它由什么构成、何时发生”。
4. **协作与交付（上下文入口）**：新建、保存、测试、导出，以及未来的 AI 协作抽屉；语义是“如何开始、继续和交出去”。

未来 AI 不占用整页工作区。它应作为可唤起的协作抽屉，读取当前选择、当前场景、素材或 FX 上下文，给出可预览且可撤销的局部提议；用户始终可以回到上述四个区域完成手工调整。

## 重构 v1：结构树—舞台—Inspector—编排器

首轮采用“左结构 / 中舞台 / 右 Inspector / 下编排器”的稳定布局：左侧上方展示场景树、下方展示可收起素材库；中央只承载工具与 Canvas；右侧以当前选择为唯一真相，提供属性 / 动态 / 效果；下方以时间刻度、场景段、当前对象显示时段和当前效果时段组织时间。

局部 FX 在左侧结构树中显示为绑定元素的视觉子项，但继续使用独立 `fx.layers` 数据；时间轴对象焦点取代卡片头 `[S]` 弹窗。完整线框、字段映射、格式边界与分期见 [UI_RECONSTRUCTION_V1.md](UI_RECONSTRUCTION_V1.md)。

## 首轮重构边界

- 保持现有画布、素材、图层、FX、时间轴和导出能力及其数据语义不变；本轮先重新组织入口、层级和呈现密度。
- 高频：选择、添加素材、添加图层、播放、保存、撤销/重做，应在不展开深层面板时可见。
- 中低频：FX 参数、蒙版细节、导出选项、兼容诊断，采用分组、折叠和按选择对象出现的方式呈现。
- 同一任务只保留一个明显主行动；例如导出面板内先选“产物”，再显示对应的帧率和时段设置。
- 任何未来新增模块先映射到四个区域之一，不能以独立浮窗长期游离在工作流外。

## 维护规则

- 每个页面/面板以“用户任务 → 入口 → 主操作 → 次要操作 → 退出/反馈”描述。
- 信息层级变更先更新本文，再落地 HTML；若影响用户工作流，同步 README 与 CHANGELOG。
- 线框、整页参考截图和标注图放在 `docs/design/assets/`；一张整页标注图优先说明位置关系，局部图补充组件细节。
