# 效果审阅页 V2：默认修订与控件接入

日期：2026-10-23。意图：在原预览上增加低阻力反馈，沿用暗色／黄色视觉；不是重新设计产品风格。用户直接看效果、改名称、备注、确认，不再下载文件后复述。覆盖当前图样候选；状态模块可供未来加样／采样使用，不代表其生产面板已迁移。

## 当前完成

- 默认可修改图样名称和参数名称，输入采用下划线；参数按稳定key写备注。名称不改变引用ID。
- 顶部“修订重置／确认本轮修订”。没有名称、备注或默认值建议的变化时，确认文案为“确认本轮通过”。普通调参不计修订。
- 参数区标题右侧“重置”负责试验值和时序，反馈不丢；修订重置不改画布试验参数。修订重置同时取消本轮确认。
- 时序试验在参数标题下，使用独立虚线框和侧边标记；原时序行为不变。
- 单项备注渐进展开，总体备注始终可写；可明确采用当前基础值作为默认值建议，目标段不自动成为默认值。
- 输入、反馈与确认存在`localStorage`，按候选ID、版本和定义指纹分开；同源同浏览器刷新恢复。指纹用于误配检查，不是密码学完整性或代码信任证明。
- 修改名称／备注／试验设置后取消旧确认；播放时间和画面分辨率不作为修订输入，不在动画逐帧存储或序列化定义。
- 保存失败显示“保存失败”；确认不能保存则不保留成功状态。空白名称不能确认，失焦恢复原名。

状态合同：`editor/effect-review-state.js`。审阅记录为`tosampool-effect-review/v1`，包含subject、review、preview及`transport: local-only`。review含name、labels、notes、note、defaults、confirmation；preview含base、target、armed、duration、experiment、transition。

通过`window.patternReview.review()`可读；确认触发`tosampool:effect-review-confirmed`页面事件。**尚无Agent回传适配器**，UI明确显示“本轮已确认 · 未回传”。事件不是网络发送；新的Agent对话也不会天然读取另一浏览器的localStorage。后续接宿主桥时沿用该记录并提供接收回执，不新增第二套反馈。

建议Agent流程：读取已确认记录 → 校验候选身份／版本 → 逐项给出采纳／替代／待确认 → 新候选版本与短差异表。默认值、显示名可直接落实；能力变更必须先验证。确认提案不等于安装、运行第三方代码或共享发布。

## 控件复用不能靠外观相似

现状核对：正式编辑器已有`EditorClassicV4ColorControl.controls`，内部优先调用`colorField`；图元拓展的`paint()`也已调用该适配器。受限provider当前只覆盖其有限参数类型；双色放射仍是候选，不能宣称候选的color/alpha已被正式provider支持。预览仍使用原生输入，不是正式颜色面板。

下一阶段正式接入必须建立控件绑定，不能从参数type自动推导出所有UI：

| 绑定声明 | 要求 |
| --- | --- |
| 控件语义 | paint，而非两个无关联的color和number |
| 字段 | 明确colorKey与alphaKey；保留Runtime底层独立字段 |
| 实现 | 调用现有颜色组件，不复制实现；缺组件时报未支持，正式接入不得静默生成原生替代品 |
| 单位 | alpha存0～1，用户显示百分比；转换只做一次 |
| 改变回调 | 沿用实时预览／最终提交，打开取消及关闭行为与其他颜色控件一致 |
| 时序 | 通过现有参数能力门控写所属对象轨；组合颜色入口明确映射两字段，不另造图样轨 |

控件绑定应作为可验证元数据进入候选／正式manifest，而不是Agent记忆中的约定。本轮未擅自新增正式格式字段；实际schema变更与生产接线仍待集成阶段。

验收四个落点：声明检查两个字段存在且无重复消费；组件注入spy证明调用的是既有组件；真实浏览器改颜色／透明度即改变Canvas且只有一套控件；撤销、Step/Linear、保存重开和HTML导出保持同值。同样方法推广到蒙版、图样和数值控件。正式页面单独实现了一套“看起来一样”的面板，不算通过。

## 截图启动问题调查

本轮实际对照：

1. 沙箱中Chrome独立临时配置启动，约1020ms退出，退出码4294930433；stderr含`TransactNamedPipe: 管道已结束 (0x6D)`与`crash server failed to launch, self-terminating`。未进入页面加载。
2. 截图工具默认优先Chrome，启动等待只监听stderr的DevTools地址，没有提前消费浏览器退出来报错，于是提前退出表现为15秒“启动超时”。没有证据证明所有历史超时同源。
3. 沙箱Edge最小启动可输出DevTools地址，但完整截图曾调试连接失败，Playwright也出现过crashpad管道错误。因此“换Edge”不是充分修复。
4. 宿主Chrome最小启动可输出DevTools地址；宿主Edge运行真实审阅测试、截图均成功。支持结论：本轮主要受当前沙箱浏览器进程／调试通信边界影响，不是图样渲染卡住。尚未定位到更底层的Windows安全策略名称，不臆测权限细目。

项目新增`scripts/capture-ui.mjs`，明确浏览器（默认Edge，可用CHROME_PATH覆盖）并调用现有截图Skill，不复制截图实现、不修改全局Skill。当前可靠执行需在获准的宿主环境运行。每次无头浏览器使用独立临时配置，不使用用户浏览器数据，不扩大网络监听范围。

剩余改进：截图Skill内部应监听早退、记录stderr／退出码、区分启动与CDP连接超时；该Skill安装在工作区外，本轮未修改。项目入口不能解除沙箱限制，也不能自动越权。遇到同类已知错误不重复盲试15秒，不以无限增大超时掩盖退出。
