状态：静态几何／图片Alpha与亮度蒙版的数据小批完成，无新面板。不是整个RC2-c结案：对象来源闭包、排布／端点引用及带父组的蒙版坐标转换仍待RC2-c2。用户已要求未来亮度来源与绘制扩展继续共用组件，本批建立同步落点，不提前实现这些新能力。

## 唯一共享落点

`editor/vnext-mask-state.js`仍是对象蒙版、场景滤镜范围与粒子范围的共享状态模块。本次在其内部增加冻结声明`PORTABLE`及以下纯数据适配API：

| API | 职责 |
| --- | --- |
| `portable(mask)` | 校验当前支持的几何、通道、精确来源及跟随基准；保留非坐标／非引用的附加配置，规范化Alpha图片的imageId别名 |
| `references(mask)` | 根据类型声明返回带kind的asset／entity引用，不猜测所有带Id的字符串 |
| `remapReferences(mask, {asset, entity})` | 按身份域重连，素材和对象即便同名也不混用 |
| `translate(mask, dx, dy)` | 复制并平移几何及followMatrix平移项，不修改输入、不改变尺寸／旋转／通道／反相 |

元素预设只调用上述模块，不自己枚举蒙版类型、图片通道或重写几何逻辑。资源内核通过元素适配器的`references/remapAssets`处理闭包，不再对整份元素预设做通用assetId字符串重写。

现有声明：rect／ellipse为box，poly为points，alpha为box＋assetId＋alpha/luma通道，element为targetId对象引用。**这不是任意模块自动可移植的承诺**：新增类型必须扩展声明与几何适配；新增引用必须标记身份域；新通道仍需对应Runtime实现。测试强制`PORTABLE`覆盖`TYPES`全部条目，未知类型／通道／未声明引用明确报错，不降级为旧蒙版。

## 当前可用的元素预设范围

- 无父级的普通／程序元素可保留矩形、椭圆、多边形和图片Alpha／luma蒙版；沿用RC2-b收集其素材和原图／recipe／Alpha链。
- 根对象入库位置归零时，蒙版场景坐标减去根基础x/y；放置时加上实例新位置。多边形平移每个顶点，box仅平移x/y，不改变w/h。
- followMatrix保留线性四项，只平移两项锚点。若位置增量为T，则蒙版几何与基准B均变为T×原值；运行时的`当前矩阵 × B逆`不会重复施加位移。
- 不跟随的蒙版只在实例初次放置时重定位；之后用户移动元素，蒙版仍按原有绝对场景语义保持不动。跟随打开则沿用既有变换和基础循环动态。没有新增蒙版动画或时序机制。
- 两个实例的蒙版是独立深副本；预设仍在局部原点保存，不被某次放置回写。对象处理pipeline与通道／反相不改变。
- 带父级的蒙版对象明确拒绝：移除父组后，原场景几何不能只减去局部x/y；旋转／斜切椭圆等还需一般仿射处理。不能为了声称支持而丢掉蒙版或保留父组影响。
- element对象来源、排布与端点引用仍由RC2-c2统一处理；`references`已经能描述其身份，但本批元素预设校验仍拒绝这些来源。组／粒子根节点继续遵循D1暂缓。
