# ASCII 默认8px混合与可选16px

本合同替代同日“默认16px混合”选择；旧16px报告保留为历史，不再定义当前默认值。

## 当前合同与四层落点

| 落点 | 变更 |
| --- | --- |
| Registry／数据 | 仍使用既有font字段，默认builtin；新增选择值chill-16，不新增参数。全部沿用Step。 |
| Inspector | 默认像素字体＝原内置8×8符号＋寒蝉7px扩展；另有寒蝉点阵体16px。先异步ensureBuiltinFont(nextValues)，再preparePatch，与字符同批写入。 |
| Runtime | 默认内置掩码不变；扩展以8px em、整像素居中烘焙，Alpha≥128置255。16px整套采用该字体，不混用2倍内置符号。按最终Alpha统一排序／LUT。 |
| 测试 | 内置逐像素、二值点阵、独立懒加载、16px整套、真实Inspector切换、撤销／项目恢复／导出；CPU/GPU回归与桌面WebView定向复测。 |

官方7px WOFF2原文件886,012字节；16px保留既有固定哈希镜像资源，来源边界不变。各自独立按需读取。默认纯符号不加载任何字体；扩展时仅加载7px，选择16px才读取16px。来源／许可证见assets/fonts内两份README。

已经保存的8px或16px glyphAtlas仍直接播放，打开不重烘焙；显式更换字体或编辑字符时才重建。单元尺寸／字形比例不会因增加扩展字符自动改变；切换字体沿用既有初始化比例规则。输出只包含已用字形Alpha，无整套字体、网络或环境字体依赖。

CPU缓存仍为最多12张图集；对象接入后每SurfacePool的GPU近期图集采用最多4张／4MiB的LRU，单张超预算时可独占。默认每字符64字节原始Alpha，16px每字符256字节。字体栅格化仅作者编辑时发生；不增加逐帧字体调用。

测试产物v4-ascii-mixed-glyphs.png/json现记录8px默认方案；历史16px数字见旧实施文档。桌面定向使用现有exe加载本机最新v4页面，不代表打包资源或原生文件对话框验收。

## 实测结论

- 14个内置符号与冻结8px参考逐像素相同；A/a/中/界扩展均为二值点阵，「界」内部空隙额外断言，防止白色文字对比增强造成填实。
- 默认18个字形原始Alpha共1152字节，相比默认16px混合的4608字节缩为四分之一。20帧字体绘制／测量0次，GPU字形上传1次。
- 浏览器实际下拉切换8px／16px、撤销、工程恢复、HTML导出通过。旧16px图集不隐式迁移。
- CPU参考40组、GPU分析22组及回退／释放通过；统一verify-v4通过。最后的小字黑色烘焙修正另外通过定向浏览器和桌面WebView检查。
- 桌面WebView与Edge的扩展Alpha密度一致，未修改Tauri默认入口，也未重新制作安装包。
