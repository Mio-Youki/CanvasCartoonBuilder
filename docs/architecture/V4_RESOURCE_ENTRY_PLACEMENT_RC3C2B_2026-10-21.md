# RC3-c2b：图样、程序构件和烘焙入口归位

状态：三类现有入口已归位并通过针对性验收。用户明确要求归位这三类入口；本批只迁现有能力，不提前决定RC5完整目录、RC6实例排序或RC4普通元素烘焙／删除协议。RC3-c2仍未整体结束，完整资源包归档动作尚未全部归位。

## 操作合同

存量流程收口，沿用侧栏及现有按钮、details折叠、状态反馈，不另开混杂资源类型Tab。用户应在所处理对象的目录找到管理操作，不再为程序新建／图样版本／烘焙切换到收藏。

| 能力 | 归属 | 保留的结果与边界 |
| --- | --- | --- |
| 图样定义／资源包导入、保存所选图样预设、项目预设新建、应用版本／停用 | 图样目录下“图样管理” | 仍调用Resources与PatternLifecycle；停用保留缓存，可撤销；不自动升级旧实例 |
| 程序资源包导入、保存／取用实现、新建 | 素材→项目下“程序构件” | Module定义不是完整元素；导入和列表不执行源码，新建需当前工程显式信任 |
| 冻结当前帧／烘焙序列、预算、进度、取消 | 素材→项目，选中程序对象时“烘焙” | 复用同一ModuleBaker与控件；不含背景／场景滤镜，不替换原对象；普通元素卡烘焙仍留RC4 |
| 原已存纯图样／纯Module包 | 对应管理区内“已存…” | 同一旧packages存储的类型投影，不另存副本；取用仍复制工程依赖 |
| 混合包、原素材包迁入、完整包导出／移除恢复、缺失提示 | 旧收藏过渡入口 | 继续可访问；不猜测成单一素材或静默删除，待后续收口 |

图样管理不作为启用状态栏；保存预设不是对画布实例实时联动。先用折叠管理区补齐现有操作，不将所有定义版本永久摊在基础目录，也不修改已确认的新建／应用规则。

## 四层落点

- 数据／Registry：不增Scene字段、资源kind和发布格式；已有库按根类型筛选，混合包不伪装为纯图样／Module。
- UI／命令：PatternLibrary提供不被目录重绘清除的管理挂载位；新ResourceEntryController只投影及路由，调用既有ResourceController命令。原烘焙DOM迁位，不另写第二套预算控件；正式页面旧重复入口收起。
- Runtime／Host：ModuleBaker、信任加载、资源闭包、缓存停用和Host保存仍用既有实现。切工程后异步操作拒绝提交；UI卸载恢复／清理挂载与订阅。
- 测试：从新入口导入图样与Module；预设新建／版本停用与撤销；取消／确认信任及跨工程隔离；冻结／序列／取消／预算；共享范围不露出项目专属管理；目录重绘不抹掉管理区；旧收藏剩余操作回归。

## 用户路径对照

从已有对象出发，本批减少寻找跨类型入口，而不承诺减少必要确认：图样版本操作不必离开图样；程序新建不必先去收藏；选中构件烘焙只需打开素材项目区。显式信任、预算、取消和原包操作均不省略。

目前“保存所选图样”沿用原能力，仅支持自定义图样，不假称附着式刻度／排布的任意预设已开放。程序“保存到库”保存实现和Manifest默认值；保留某个实例的已调参数，应通过结构树“库”收入元素素材。已存图样／构件是同一packages库的管理投影，不是普通素材共享发布，也不新建第二份持久化库。

`classic-v4-resource-entry-controller.js`是UI层；ResourceController暴露带工程guard的importFile、状态／库变更／停止订阅及烘焙挂载。原完整包归档列表继续复用同一library。卸载新控制器会取消订阅并归还烘焙DOM；停止命令控制器会同步卸载新入口。项目／共享范围统一隐藏带data-material-project-only的管理区，烘焙区额外要求单选完整程序对象。

管理内容只在资源定义／选择相关字段变化时更新；不为每次Canvas拖动重新序列化内联Module源码或重建同一烘焙控件。周期帧数输入与折叠状态不会因无关变换被重置。图样基础目录重绘只更新catalogue，不清空管理挂载位。
