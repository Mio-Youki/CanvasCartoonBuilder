## 用户如何验收

1. 可直接用项目图样栏的“导入图样”，打开`examples/resources/dual-ray.tosampool-resource.json`。这个仓库示例包不伪造用户确认、不写入用户共享数据库。
2. 也可以重新启动`node scripts/serve-effect-review.mjs`，打开`http://127.0.0.1:8780/examples/pattern-proposals/dual-ray/preview.html`。确认后由本机服务生成正式包，同源审阅页自动加入共享库；编辑器在同源地址打开。
3. 未选中载体时可从图样栏新建；选中矩形、椭圆或多边形时可应用，保留几何轮廓。项目仍每图样一个预设，不增加另一套收藏库。

已有旧进程不会热更新代码。原任务和确认记录保留；实现指纹改变后需重新确认，旧任务重试不能自动授权新实现。没有配置真实Agent时，名称／默认值等确定性交付可用；备注类迭代仍明确阻塞，不假装调用模型。真实模型外发授权、持续会话Harness、MCP写入和Tauri尚未完成。

## 四层落点

| 层 | 改动 |
| --- | --- |
| Registry | `patternProviders`接收受控生成器声明，仅解析已登记实现；声明与实现的参数语义、预算和组件必须一致。允许项目内名称／标签／默认值及版本修订，不允许偷偷扩展数值范围或换代码。 |
| Inspector | 拓展页使用既有`EditorClassicV4ColorControl`，两项颜色各自只显示一套颜色＋透明度组件；时序按钮仍分别绑定对应字段。动态开关展开周期／方向；载体／方向显示中文选项。绘制型图样不再显示无效的旧单色描线外观。 |
| Runtime | 仓库实现`59l-dual-ray-pattern.js`输出受控绘制计划；真实载体轮廓、秒制时间进入内容绘制。预览与正式图元共用实现，不再用测试Scene Module包装图样。旋转被播放调度器识别。 |
| 交付及测试 | 复用原定义生命周期、SHA256资源包、项目保存重开、共享库和内联Runtime。增加静态双色绘制快照，停用生成器后保留颜色，不降成黄色轮廓。 |

`implementation`是显式实现版本标识；审阅额外使用登记函数／载体构造函数的指纹，变化会使确认失效。该轻量指纹只用于审阅失效，不是安全签名；资源包SHA256检查数据完整性，也不代表任意代码可信。图样包依赖当前Runtime中已随应用发布的实现，本批没有建立通用第三方JS模块加载器。

## 参数与前端同步事项

稳定ID维持`proposal.dual-ray@1`，显示名“双色放射”。

| 参数 | 默认值 | 时序 |
| --- | --- | --- |
| 载体 | 矩形 | No |
| 色块对数 | 12 | Step |
| 颜色一／透明度 | `#e6dec8`／100% | Linear |
| 颜色二／透明度 | `#9c9888`／100% | Linear |
| 中心X／Y | 0.62／0.58 | Linear |
| 起始角度 | 0 | Linear，直接角度插值 |
| 色块占比 | 0.5 | Linear |
| 动态·旋转 | 开 | Step |
| 周期时间 | 12秒 | Step |
| 方向 | 顺时针 | Step |

组件变更点位于`classic-v4-path-extension-control.js`，不是HTML新增一套取色器。`controls`里的`color-alpha`绑定两个数据字段，但只生成一组控件；不要在新版前端按parameters逐项重新展开alpha。`when`控制渐进显示；`labels`为选择值的显示名称，保存的稳定值不变。批量颜色写入共用已有历史事务；颜色／透明度时序仍可分别启用。

图样库`classic-v4-pattern-cards.js`增加生成图样的载体兼容和应用路径；单个顶层形状应用时变为矢量对象＋图元，父对象变换保留。没有引入专门的“双色放射”孤立面板。

## 渲染与成本

- 算法保留原审阅的扇区角度、中心、半径计算、顺逆时针和不透明底色策略，默认外观不重画。
- 不透明首层使用`fillCarrier`复用已有裁切路径。此前大椭圆在默认画布上有数千个轮廓点，重复展开为普通指令会误触发1024指令预算；复用后遵守独立的载体点数预算，128对／1920×1080椭圆也有夹具。
- 对象整体透明度最后合成。包含绘制计划的对象在非100%整体透明度时走现有离屏池；图元自身透明度也先合成图样再乘算，避免颜色透底。透明度100%、无对象效果时仍走直接路径。
- 没有像素读回。加样／采样／蒙版需要离屏时仍由原对象处理管线承担，不能把额外后处理成本解释成放射算法成本。

本机无头Edge定向测试，预热12次、60次同步绘制，默认12对：多轮正式对象无效果P95约0.4–1.3ms；最终记录为960×540约1.3ms、1920×1080约1.1ms，两档均为0像素遍历、0离屏峰值。另一个持续运行审阅页的150帧夹具约1.3ms。后台负载与计时范围不同，不据此承诺固定比例；均不代表GPU完成、显示合成或整页UI帧时间。
