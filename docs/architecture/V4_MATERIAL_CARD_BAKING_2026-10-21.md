# 素材卡烘焙与项目／共享卡对齐

本批为存量流程补齐，沿用现有面板、颜色和图标语言；不是Runtime效果重构或新视觉主题。用户任务是“把这个可调元素变成能独立使用的图片或序列”。

## 已实现

- 元素素材卡左下，位于位图α对应位置，增加▧烘焙入口。普通元素和程序元素共用；不要求先加入画布。
- 浮层仅提供位图／序列。位图默认使用打开时的播放时刻，可调整；序列提供周期帧数，时间为当前项目周期，均匀采样且不重复最后一帧。
- 输入是素材卡已保存的基础参数，不是画布上某个实例的未回存修改。不携带项目时序、场景背景、场景滤镜和无关对象；保留入库的基础循环动态、图元及对象效果。
- 按输出帧计算共同对象边界，裁切为局部透明画布；含已声明的效果外扩和运动边界，不输出整幅项目画布。新素材保留出处记录，但运行不依赖原程序。
- 完整成功后单历史入库并选中新素材。原元素素材和画布对象不替换。关闭／Esc取消、切换工程或版本变化都不写入半成品；失败留在面板，可修正参数。
- 复用现有120帧、单帧4MP、总采样96MP及编码48MB预算。超预算明确拒绝，不静默降低质量。程序仍需已在当前工程导入时授权，不新增信任弹窗。
- 删除共享卡残留的`display:flex`专属覆盖规则。项目和共享直接共用网格、预览比例、名称、按钮24px尺寸和右上×／右下→的位置，不再把按钮排到预览下方。
- 项目已共享卡左上♥悬停／键盘聚焦显示↥；title和aria-label始终为“更新共享素材”。不改变单向更新／共享页移除的语义。

## 四层落点

| 层 | 落点 |
| --- | --- |
| 数据与合同 | `v4-material-baker.prepare`建立隔离预设实例和共同边界；复用现有元素预设、Module授权与素材结构，不增加效果Registry或运行字段 |
| UI | `classic-v4-material-bake-controller`负责快照、浮层、计划、取消、原子入库；素材控制器仅挂入口。共享控制器提供两个图标状态，CSS删除冲突规则 |
| 绘制 | `v4-module-baker`复用Full对象绘制，仅显式material路径接受普通元素和viewport；原构件烘焙API默认范围保持不变。正式逐帧Runtime算法未改 |
| 测试 | 新素材烘焙合同／浏览器夹具进入`verify-v4`；旧构件烘焙像素回归和共享流程继续通过 |

`assets[id].moduleBake`沿用已有来源元数据；普通元素不伪造moduleId，`scope: "element-preset"`附带presetId与viewport。该记录不构成运行依赖，不将输入元素实例写入新位图。

## 验证与证据

- 合同：大项目画布仍按对象局部裁切、默认只读、无其他对象／时序、共同动态边界、帧数预算及无重复尾帧。
- 浏览器：普通位图与4帧动态序列、图片与超出其原边界的附加图元完整烘焙、程序素材无需先上画布、拒绝额外信任、原对象保留、撤销重做、工程保存重开、超预算、运行中取消、换工程关闭。
- UI坐标断言：项目／共享预览宽高一致，×／→都在预览内，相对Y一致；悬停后♥隐藏、↥显示，可访问名仍是更新。
- 原构件Full像素、8帧序列、编码失败、取消、过期、无Module交付回归通过；原共享发布／CAS更新／移除／刷新持久化通过。
- 自检截图：`tests/artifacts/rc3-material-bake-dialog/page.png`、`tests/artifacts/rc3-shared-card-alignment/page.png`，1440×1000，已查看。截图工具仅报告favicon 404。沿用按压反馈，hover图标直接切换，不新增装饰性动画。无独立视觉评分。

未运行全量verify-v4、Tauri封装或新的性能压力基准。旧画布构件烘焙入口继续保留，不在本批删掉相关API；组／粒子入库、旧收藏完整包归档和素材自动重开仍是后续工作。
