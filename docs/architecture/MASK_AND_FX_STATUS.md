# 蒙版与局部合成：已交付边界

> 本文是当前 Runtime、编辑器、导出与 Agent 合同的共同收口说明。字段的机器可读定义以 `../../SCENE_SPEC.md` 为准；未来增加能力时先更新该规范，再同步本文、README、PLAN 与 CHANGELOG。

## 已完成

### 1. 统一蒙版

任何由通用 Runtime 绘制的实体图层都可使用 `mask`：图片、图元、粒子、通用程序元素和兼容 builtin。支持：

- `rect`：矩形；
- `ellipse`：椭圆；
- `poly`：多边形；
- `alpha`：素材 Alpha，或亮度映射（黑透明、白不透明），可反相。

蒙版限制的是该图层的最终可见区。粒子的 `x/y/w/h` 仍只表示**出生范围**，两者可并用、不可互相替代。

编辑器采用统一绿色编辑态：矩形/椭圆可框选、移动、缩放；多边形支持点选建立、双击或 Enter 闭合、拖点、边上插点和删除点；Alpha 蒙版可在画布内半透明对齐。蒙版层不会被当作普通图片、普通元素或新的蒙版候选项再次嵌套。

### 2. Alpha 素材生命周期

从素材库选中图片作为 Alpha 蒙版时，编辑器会冻结处理后的快照，作为 `images[]` 中隐藏的 `role:'mask'` 素材；目标的 `mask.imageId` 仅引用该稳定 id。保存后的 js 因此保持自包含，不依赖原文件地址。

替换或清除蒙版、删除引用元素或局部 FX 后，未被其他蒙版引用的隐藏素材自动清理。当前浏览器版不会保存原图路径或处理配方；这些“可重连素材库 / 项目目录”能力明确留待桌面应用。

### 3. 局部 FX 与蒙版

`fx.layers[]` 是独立的有序局部合成层。每项用同一套 `mask` 限定效果范围，而不裁掉场景实体。已交付的轻量效果包括：颜色与混合模式、像素雾、硬边像素光晕、局部暗角、确定性噪点、扫描线、局部 CRT、故障、局部采样/色板/调色。

固定渲染顺序：

`实体图层 / 粒子 → 全部局部 FX → 全局像素处理 → 全局叠加 FX → 场景过渡`

局部 FX 可绑定稳定元素 id：

- `anchor`：自身蒙版随目标移动；
- `clip`：在 anchor 基础上，再裁入目标的实际 Alpha 与目标自身蒙版。

两种绑定均会跟随目标的 `scroll`、`bob`、`spin`、`wave`、`pulse`、静态旋转、缩放、镜像和 blink。删除目标只解除绑定，保留效果层。

### 4. 导出与兼容性

编辑器预览、固定时间 Runtime、PNG/Sprite PNG/多帧 PNG/GIF 与“测试场景”使用相同的 Runtime 绘制路径。因此，以上蒙版和局部 FX 的视觉语义可随自包含 js 一起迁移；不要求宿主网页额外安装滤镜库。

`HOME_SCENE` 的专用兼容绘制函数仍可与通用 Runtime 同时存在。通用可编辑性诊断不应阻止兼容脚本的预览与帧导出；它只提示后续图形化编辑的覆盖范围。

## 当前明确不做的能力

- 高斯模糊、边缘羽化与任意卷积滤镜；
- 蒙版嵌套、布尔运算、合成组与调整图层；
- 可重连的原图/处理配方/跨项目素材库；
- 任意自定义 JS FX 函数；
- 关键帧曲线、蒙版形状随时间插值。

这些不是格式缺口：现有 schema 会安全忽略未知扩展字段。未来若实现，必须保持当前 `mask` 与 `fx.layers` 的基础语义不变，并评估对自包含 js 运行时体积和离线导出的影响。

## Agent 使用原则

Agent 应优先把蒙版用于“真实可编辑边界”：水面波光范围、树冠/角色轮廓、局部夜色、雾区与受限 FX。不要为模拟复杂静态纹理而滥用数百点多边形；高密度静态细节仍应判断为图片基底，再在其上增加有编辑收益的图元、粒子或局部效果。

生成时：`mask.type:'alpha'` 必须指向已存在的稳定 `images[].id`；局部 FX 的 `bind.targetId` 必须指向已有且稳定的顶层元素 id。完整字段与反例见 `../../SCENE_SPEC.md`、生成策略见 `../agent/AGENT_GENERATE_SPEC.md`。
