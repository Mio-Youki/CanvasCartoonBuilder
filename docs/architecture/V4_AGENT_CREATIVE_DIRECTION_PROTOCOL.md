# ToSampool v4 Agent 创作方向协议

状态：**v1 / C1 质量轮启用。**

## 为什么它独立于 Scene 合同

Scene 合同回答“工程怎样可以运行”；Context Pack 回答“可以选择什么载体”。两者都不能自动回答“一个雪花球应该如何看起来像雪花球”。

若把构图、层次和风格要求继续翻译成底层 `x / y / rect` 参数，Agent 会变成格式填表器，既不能提升美术判断，也不能向用户解释设计取舍。因此创作方向是单独、冻结、可审阅的一层输入。

```text
一句话意图
  → 方向卡 / 用户确认
  → Creative Direction
  → Context Pack（能力与工程骨架）
  → 隔离 Agent Draft Package
  → 固定时间预览 / 人工审阅
```

## 1. 最小格式

`context.json` 可选包含 `creativeDirection`。它不进入 Runtime，不是 Scene 的一部分，也不替代人类审阅。

```json
{
  "format": "tosampool-creative-direction/v1",
  "title": "冬夏秋雪花球",
  "visualAnchor": "带明显玻璃体积和玩具感的像素雪花球",
  "composition": [
    "球内所有主景必须裁切在圆形内景边界中",
    "底座、球体、内景三个层级应有清晰比例",
    "内景至少有远景、中景、前景三层"
  ],
  "seasonBeats": [
    {"sceneId":"winter","focus":"木屋暖窗与降雪"},
    {"sceneId":"summer","focus":"水草、游鱼与上浮气泡"},
    {"sceneId":"autumn","focus":"红杉纵深与落叶"}
  ],
  "motion": ["环境运动应次于主体轮廓", "转场从完整场景切换，不用独立假扫描条代替"],
  "avoid": ["用矩形底图遮住球内构图", "只有一个主体加随机粒子", "所有细节同一尺寸"],
  "selfReview": ["四个固定时间点都能读出当前季节", "球内景不越过容器", "三季不能同时可见"]
}
```

## 2. 输入与责任划分

| 来源 | 提供什么 | 不提供什么 |
| --- | --- | --- |
| 用户 | 一句话、参考、必须保留对象、偏好或排除项 | 底层节点、采样参数、坐标 |
| Agent propose | 两到三张方向卡；每张说明视觉策略、载体和编辑粒度 | 直接改当前项目 |
| 用户 | 选择方向或修正一项结构性判断 | 填写完整工单 |
| Creative Direction | 构图不变量、层次、节拍、运动重点、禁止项、自检点 | 可执行 Scene 或 Runtime 代码 |
| Context Pack | 载体、Module 合同、文件骨架、运行边界 | 美术模板与强制构图 |
| Agent build | 选择实现方式并交付 Draft Package | 修改 Runtime 或绕过审阅 |

这样既保留 Agent 的程序绘制自由，也让“看起来对”有明确、可评审的标准。

创作方向可以声明视觉锚点、容器关系与层次比例，但不能自行发明坐标语义。它必须配合 Context Pack 的两层坐标合同：普通 Scene 实体按左上角定位，Module 内部按中心局部坐标绘制；“居中”这类自然语言要求需要由 Agent 明确换算为相应一层的坐标。

## 3. C1 的方向卡

本轮固定使用“玩具微缩景观”方向：玻璃球为圆形容器，内景在局部坐标中先圆形裁切；季节内景有远景 / 主景 / 前景；粒子只作为空气层；玻璃与底座在内景之后绘制。

这不是产品永久风格。它只是确保 C1 的成功条件不是“出现了一间木屋”，而是“完成了一个可辨认、可编辑、可循环的雪花球”。

## 4. 质量轮纪律

1. 创作方向变化与工程协议变化不能同轮发生。
2. 每轮保留未经人工修补的初稿和固定时间预览。
3. 预览问题先归因：构图 / 载体 / Runtime / 性能；只修其中一类。
4. C1 通过后，C2 与 C3 复用相同格式，但各自定义不同的构图不变量。
