## 1. 当前“下载提案参数”是什么

下载文件名固定为 `dual-ray.proposal.json`，格式为 `tosampool-pattern-proposal/v1`，状态为 `awaiting-visual-review`。

| 内容 | 实际含义 |
| --- | --- |
| id / version / name | 候选身份、版本和当前名称 |
| parameters | 参数声明：key、显示名、类型、范围、默认值及 No/Step/Linear 等候选元数据 |
| base / target | 当前基础值和目标值；target 中未启用时钟的值不等于已参与时序 |
| armed | 实际参与目标段时序的参数 key |
| duration / experiment | 预览总时长、是否开启时序试验 |
| track | 用当前端点与中段模式生成的三段试验轨道 |

它是审阅状态快照，不包含生成器实现、Runtime、参考图片、预览网页、截图、正式载体注册或发布证明。没有正式图样包所需的完整实现链，不能导入共享库，也不会自动回传当前 Agent。现阶段可将 JSON 附给 Agent，由 Agent 对照同版本候选读取；页面尚无导回该 JSON 的功能。

注意：experiment 关闭时仍会生成 track，因此消费者必须尊重 experiment，不能擅自把试验轨写入正式默认值。中段方式目前由 track 的段类型表达，没有独立 transition 字段。正式交接应显式记录，不能依赖 UI 外观猜测。

## 2. 建议把模板变成“可提交的审阅台”

### 2.1 首批建议支持

- 图样名称：编辑展示名，稳定 ID 不变。
- 参数显示名：在任何段都可改名，但全局只保留一个名称，所有段和正式 Inspector 共用；绝不改参数 key。
- 默认参数：明确“基础值作为建议默认值”；目标段只是时序例子，不自动取代基础值。
- 参数可见性：选择常用／更多参数，提出隐藏建议；隐藏不等于删除能力或改变旧数据。
- 单项备注及总体意见：例如“中心改为放射中心”“旋转速度仍太快”。
- 审阅决定：请求修改／确认外观与参数。确认不是安装、代码信任或共享发布授权。
- 导出审阅结果、导入并恢复同一候选的审阅记录；后续桥接就绪后再增加提交给 Agent。

改名宜通过显式编辑名称入口，避免与数值输入和时钟点击冲突。不应只允许改“目标段参数名”，因为它们是同一参数而不是新的目标参数。

### 2.2 不应允许无校验改动的部分

用户可以请求修改范围、单位、No/Step/Linear 或增加参数，但不能靠改文字就宣布 Runtime 已支持。类型变化、整数变连续、插值方式、载体范围、新绘制原语等属于能力变更，必须重新校验实现和预览，再返回审阅。不能以自由 JS 输入替代安全的正式图样协议。

### 2.3 建议审阅记录协议（待实施）

使用独立的 `tosampool-pattern-review/v1`，而不是让用户编辑候选实现定义。至少包含：

- 候选 id、version、定义摘要；审阅修订号。摘要覆盖候选参数与实现，防止意见应用到另一版候选。
- decision：request-changes 或 approve-proposal；图样显示名及按稳定 key 索引的参数显示名。
- base、target、armed、experiment、duration、显式 transition；记录预览条件。
- 参数可见性建议、按 key 索引的备注、总体意见；能力变更请求单列。
- 提交时间和证据引用。截图可选；参数可重放不等于已经保留了视觉证据。

Agent 先校验身份／版本／摘要，再区分“文案与默认值调整”和“能力变更”。用户明确编辑的内容优先于 Agent 的旧建议；若用户文本与实际支持冲突，说明冲突并返回请求，不静默覆盖。原始反馈和 Agent 落地结果分开保留。

当前无 API/MCP 回传通道时：下载审阅文件 → 用户附到当前对话 → Agent 校验并处理。将来直连也沿用同一记录，避免另造协议。提交状态必须区分本地保存、已发送、Agent 已接收、已返回新候选。

## 3. 上轮耗时：已知证据与不可推断内容

原执行记录计时至 10:24:19：44分49秒。该数值不是上轮最终结束时间，也不是绘制一个放射图样的纯生成时间。记录包含通用时序核、正式 Inspector、候选、预览壳、浏览器环境和回归的交错工作。没有逐项独立起止记录，不能声称某个问题浪费了确定分钟数或承诺下次会减少某个百分比。

### 3.1 浮点比较：测试错误，可直接预防

原因：插值的十进制结果在二进制浮点中不一定精确，严格相等会把正确的近似数判错。

处理：连续数值断言使用与量纲／范围匹配的绝对和相对误差；ID、布尔、枚举、整数、分段边界归属仍严格比较。不要靠把所有输出四舍五入修测试，更不能用宽容差掩盖真正的偏差。

状态：本轮夹具已使用容差；还没有证明全仓库断言已统一。后续将数值断言封装成小工具，新增夹具复用。预检用已知端点／中点／边界例验证容差本身。

### 3.2 单文件截图服务：资源根范围不匹配，可预检规避

原因：预览引用候选目录外的共享 Runtime 和审阅壳；只服务单个 HTML 的工具无法解析这些相对路径。这是服务根不匹配，不是候选绘制错误。

处理：选定一个仓库内只读静态根，保持相对路径；预检 HTML、共享脚本、Runtime 都能从同一根加载，并等待页面就绪。不要为截图另复制绘制实现，也不要每次生成都临时更换服务方式。

状态：宿主只读本机服务已用于该预览；尚无统一自动启动／健康检查命令。本轮浏览器回归使用 file URL 成功，不等于它能代替所有 HTTP 场景。

### 3.3 沙箱服务与宿主浏览器隔离：环境边界，只能部分消除

原因：在当前环境中，沙箱侧启动的 localhost 服务不能由宿主浏览器访问；同一端口文字不代表同一可达环境。现有证据不能将所有连接失败都归为同一系统原因。

处理：固定服务与浏览器的运行侧，启动后从实际浏览器端检查；失败先区分未监听、资源缺失、地址不可达，最多一次诊断和一次已知替代路径，不在多个端口反复试错。仅绑定回环地址，不扩大网络暴露以绕过隔离。

状态：本轮宿主服务解决；仍受宿主权限、端口占用、会话退出影响，不承诺永久在线。后续健康检查输出明确的失败分类；缺少权限时停在预检，不开始候选浏览器验收。

### 3.4 Inspector 就绪判断：夹具错误，可直接修复

原因：顶层词法变量可被脚本访问，但不一定是 window 属性；等待 window.classicV4Inspector 会超时。

处理：本轮已改为检查实际词法绑定。长期应提供最小只读 ready/version 状态，供夹具等待真实初始化完成，而不是暴露全部内部状态或加固定长延时。测试浏览器错误、必要脚本及 ready 三者，不仅检测变量存在。

状态：当前夹具已修；统一稳定 ready 接口尚未实施。属于测试基础设施债务，不是图样视觉算法返工。

### 3.5 内联 Runtime 镜像：必须验收，不应当成可删的返工

原因：编辑器引用普通 bundle，导出 HTML 引用内联镜像；只更新前者可能导致预览正确、交付错误。

处理：一个明确的构建入口生成两者；检查两者与唯一源码同步；针对正式导出的 HTML 验证参数求值和绘制。只比较文本或只打开编辑器不能证明导出可用。

状态：本轮两份已重建，并通过内嵌 HTML 的实际求值回归；统一构建／验证命令仍应整合。应在 Runtime 集成阶段一次完成，不让每个纯候选生成都重建产品。

### 3.6 逐帧序列化定义：性能风险，缓存需合同约束

原因：如果每帧为判断能力重新遍历／序列化完整定义，成本会随对象数和定义大小增长；与放射几何本身无关。

处理：按不可变轨道和定义引用缓存过滤结果；无相关声明的对象快速返回。真正的修改必须替换引用或提升修订，否则缓存可能过期。不能通过缓存旧结果换取“快”。

状态：本轮已实现缓存并验证引用复用及基值不变；全局所有写路径的不可变约定、长时内存及大规模混合场景并未全量证明。新增测试应覆盖新轨道／新定义导致重新求值及 No 门控不被缓存绕过。

## 4. 减少交错的下一轮流水线

| 阶段 | 输入与退出产物 | 禁止混入的工作 |
| --- | --- | --- |
| 0 环境预检 | 固定预览根、脚本可达、浏览器 ready、现有基础测试通过 | 不一边写候选一边排查服务 |
| 1 能力差距判定 | 已有原语可表达／需要新增原语；明确参数和 timing | 不以预览模拟不存在的正式能力 |
| 2 候选生成 | 名称、载体、参数、一个绘制实现、交互预览 | 不写共享库，不改正式 Inspector，不为每个候选重做模板 |
| 3 用户审阅 | 可重放意见／确认记录 | 等待时间不计入 Agent 工作时间；未通过不进入集成 |
| 4 正式集成 | 协议验证、注册、控件映射、一次构建两种 Runtime | 不同时扩展无关 UI 或优化其他效果 |
| 5 验收与交付 | 合同 → Runtime → 真实输入／导出 → 预算；正式图样包 | 未达标不标发布成功；共享发布另按明确授权 |

若阶段1发现新增原语，单开“基础能力建设”任务块，完成其合同与针对性验收后再回到候选。审阅时只可声称已验证的能力，不再把基础建设时间混入纯候选生成指标。必要安全修改立即做，但记录中断原因和起止时间；其余问题进入队列，不随发现随插入。

## 5. 实施优先级与验收

1. 先做基础预检和阶段记录：一次命令检查资源／ready／测试入口；每阶段记录开始、结束、主动工作、工具等待、返工事件。无法区分的时间标未分摊，不补造数据。
2. 再做审阅记录：名称与参数标签、默认值、意见、决定、导入／导出恢复。验收稳定 key 不变、未参与目标不写默认、旧版反馈被拒绝或明确迁移、错误记录不修改候选。
3. 再统一构建与按需验证：纯候选跑候选测试；修改时序核则加合同／正式轨／导出测试；变更绘制预算则加同条件性能比较。发布前仍跑必要完整回归，不为速度取消门槛。
4. 最后接自动回传：同一审阅协议，只加运输层与回执，不把“下载成功”当“Agent 已收到”。

效率指标：候选首次可审阅时间、基础能力建设时间、用户等待、正式集成时间、验收时间、返工次数及分类。第一轮先建立基线，不预设无证据的分钟承诺。性能指标区分命令提交、完整帧、导出播放器；上轮约0.2ms提交P95不能用于证明整页无卡顿。

本次交付：解释和复盘文档，以及后续可执行顺序。未实施参数改名／意见提交／反馈导回／统一预检命令，未注册或发布双色放射。

## 6. 后续对齐：修订模式替代下载按钮（待确认与实施）

2026-10-23 用户提出：移除下载入口，以修订模式／回到预览切换；仅修订模式可改名称和备注，数值与画布不受模式影响。方向适用于图样、加样、采样共用审阅壳，不应固化图样专用字段。

建议分三层存储：候选不可变基线；始终可调的预览状态；仅修订模式可写的反馈记录。切换模式保留三层，不重置播放、参数、时序或备注。名称修改只改 label，不改变 key；返回预览后显示修订后的名称，但不可编辑，并能查看原名或撤销该项。备注绑定参数 key，也可存在总体备注。日常调参不自动变成修改请求，需明确选择“采用当前基础值为默认值”；目标段仍只是时序示例。

建议首批修订操作：名称下划线输入；参数旁备注入口（有内容才显示标记）；总体备注；单项恢复；一个明确的“确认本轮修订”动作或等价已确认状态。后者用于区分输入中草稿与可交给 Agent 执行的意见，不要求增加第二套聊天表单。返回预览仅退出编辑，不自动授权安装／共享发布。

本地记录应按候选 ID＋版本＋定义摘要隔离并自动保存，显示简短保存状态；持久化失败不得声称已保存。只存 DOM 或内存不能跨刷新；localStorage／IndexedDB 与浏览器源、配置文件绑定，也不等于 Agent 可读取。需选择同一预览服务源，并通过受限读取接口或经授权的浏览器会话读取；当前没有自动回传实现，不承诺下一次对话天然可见。读取接口应限于该候选反馈，不提供任意本地文件访问。

Agent 响应应给出逐项采纳／调整／待确认结果，文案和默认值直接按已确认意见修改；能力变更重新实现验证；返回新候选版本及短差异清单，保留上一轮反馈不覆盖。读取失败明确告知，不让用户误以为已接收。

颜色与透明度应在视图层组成一项 paint 控件，仍可保留内部两个数值字段以复用现有求值器；两者时序可合并为一个用户入口，底层按各自能力写入。预览不能因参数声明有 color 和 alpha 就盲目生成两套 UI。正式放射尚未注册，目前不能声称已自动共用正式颜色组件；接入时需显式声明字段配对并使用现有颜色组件，确保没有第二个透明度控件。

本次已实施的仅是删除预览副标题、编辑基础／目标状态说明及底部常驻教程，保留必要控件名称；操作帮助移至时序开关提示。未实现本节修订机制或颜色配对控件。语法检查通过；截图工具浏览器启动超时，本次未完成改后视觉复核。
