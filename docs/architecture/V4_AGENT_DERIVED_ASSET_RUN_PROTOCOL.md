# v4 素材衍生 Run 协议

状态：**v1 / 临时 Run 状态机与合同已实现；尚未接入真实分割、修补或生图宿主。**

## 1. 目的与边界

素材衍生是“Agent 创作”中的独立工作流。它不直接改写 Scene，也不自动将结果写进素材库：先冻结一张图源，生成可修改的任务卡，再生成候选，最后由用户逐项通过。

两种模式：

- **素材分层**（`layering`）：把图像拆为可单独使用的空间层；可选补全被遮挡或画面边缘之外的内容。
- **变体生成**（`variant`）：针对整图或单独位置框生成受约束的画面、姿态或状态变体。

“图源”是素材衍生专用的参考角色。它表示 Agent 可基于冻结像素做分割、补全或变体，而非自动把该图放进 Scene。

## 2. 用户可见的任务卡

素材分层卡固定只显示四项：

```text
01  人物        [位置框]    遮挡补全：否
02  近景山脊    [位置框]    遮挡补全：是
03  天空        [位置框]    遮挡补全：是
04  背景        [自动]      遮挡补全：是
```

1. **序号**：按视觉图层由前至后排列；它对应用户理解的绘制顺序。
2. **分离目标**：可改名、增加或删除。
3. **位置**：归一化 `x/y/w/h` 框，可在源图上移动与缩放。
4. **遮挡补全**：用户只决定“此层是否需要在原图不可见区域中仍可成立”。

“边缘延展”“遮挡区域补全”是宿主根据 Alpha、ROI 与深度关系选择的内部策略，**不额外增加用户开关**。例如天空被山脊遮挡时，宿主可补全山脊后的天空；天空位于画面边缘时，可向 ROI 外缘延展。

变体生成共用前三项；每张卡的“位置”可独立，也可为空表示整图变体。第四项改为简短的“保持不变”摘要，由 Agent 根据原始意图与用户编辑编译而成。

## 3. 两轮处理

### 第一轮：边缘与 Alpha

```text
图源 → Agent 分层计划 → 用户修改四字段任务卡
    → 为每个目标产生 Alpha / 残余蒙版候选
    → 用户审阅与修边
```

背景在第一轮只是“蒙版残余”，不是已经完成的修补背景。此轮结束后，分离层才有可靠的边缘与遮挡图。

### 第二轮：补全与变体

```text
已确认的 Alpha + 图层关系
    → 对“遮挡补全：是”的层生成内容补全
    → 或按变体卡生成图像变体
    → 审阅候选 → 通过后入库
```

素材分层在所有非背景 Alpha 获得第一轮通过前，不能开始第二轮；这避免用户修边后使先前的背景修补失效。若已通过的 Alpha 后续又被编辑，相关第二轮结果必须标为“需重制”。

## 4. 重制与三候选

重制不覆盖现有候选。每张任务卡一次最多保留三项：

```text
当前选择 A + 新候选 B + 新候选 C
```

- 首次执行可返回 1 至 3 项；
- 用户选择 A/B/C 后点击“重制”，保留当前选择，只刷新另外两个候选位；
- “通过”只接受当前选中的一项；未通过的候选属于临时 Run 缓存，不写入素材库；
- 宿主必须要求新候选做**受控差异**：分层修补保持边缘与主体，变体只改变用户允许改变的内容。

## 5. 意图、任务卡与二次编译

优先级固定为：

```text
用户最后一次任务卡修改
  > 用户原始意图
  > Agent 首轮识别与建议
```

任务卡修改后，Agent 可执行一次**二次编译**，而不是重新创作：规范化目标、检查 ROI、推导遮挡依赖、建议补全范围与成本。它不得重新添加已删除任务、扩大用户框选范围、或在未确认时执行图像生成。

若二次编译会改变像素处理范围，必须显示为可接受/拒绝的建议；纯元数据（例如内部依赖顺序）可自动更新。

## 6. 状态机

```text
planning
  → edge-review       素材分层的 Alpha / 边缘候选
  → repair-review     补全或变体的三候选审阅
  → complete          所有需入库的候选已通过
  ↘ cancelled
```

浏览器版的取消是“停止等待并丢弃未接受结果”；外部模型即使已在运行，其延迟返回也不得写入素材栏。Tauri Host 后续可增加真实的请求中断和本地临时缓存。

## 7. 数据合同

`editor/vnext-derived-asset-run-state.js` 提供不携带像素的 Runtime-free 状态：

```js
{
  format: 'tosampool-derived-asset-run/v1',
  mode: 'layering' | 'variant',
  source: { assetId, referenceId, snapshotId? },
  originalIntent: '...',
  phase: 'planning' | 'edge-review' | 'repair-review' | 'complete' | 'cancelled',
  cards: [{ id, order, target, roi, occlusionRepair, status, userEdited }],
  candidateGroups: {
    taskId: { selectedId, values: [{ id, preview, label, meta }] }
  },
  revision: 1
}
```

它不保存 API Key、模型名称、原始像素或可执行代码。实际图片候选继续走 [派生素材协议](V4_AGENT_DERIVED_ASSET_PROTOCOL.md) 的 Host 适配器与 `tosampool-derived-asset/v1` 结果合同。

## 8. 入库前实验门槛

在完整接入永久素材库前，先进行两层实验：

1. **计划与审阅交互**：验证四字段任务卡、用户编辑优先级、取消、收起/恢复和三候选选择。
2. **空间成立性**：验证人物移开后的原位置、山脊移开后的天空、用户修边后的补全失效标记，以及通过候选作为普通素材独立运动的效果。

只有第二层通过，才将“素材分层”作为对用户公开的能力，并进入项目级派生版本、持久化缓存与 Tauri 文件写入。
