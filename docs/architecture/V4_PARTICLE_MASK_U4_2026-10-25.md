# 统一蒙版U4：粒子出生批次与范围

日期：2026-10-25。承接[U3实际预览](V4_MASK_PREVIEW_U3_2026-10-25.md)，按[统一蒙版合同](V4_UNIFIED_MASK_CONTRACT.md)实现CPU核心与真实编辑器接线。**功能验收完成，不代表全量共享生命周期、GPU或Tauri验收，也不代表动态大图冷启动性能已解决。**

## 本轮确认与行为

用户已确认：数量／寿命切段时，旧粒子按出生时参数继续存活，新粒子使用新段参数；全黑或稀疏范围允许实际数量减少，不强行补满。

- 发射器平移、旋转、缩放、斜切和父组变换在出生时记录。之后改变发射器，不会搬动旧粒子；速度、方向、扩散、风力、重力、个体尺寸／透明度和旋转参数也取出生快照。
- 粒子实体仍是当前帧共享精灵：颜色／形状等视觉内容每帧求值，不为每个出生粒子永久烘焙。发射器整体透明度、父级透明度和实体自身透明度仍按当前帧乘算。
- 数量表示不受分布限制时的稳态目标；出生间隔为寿命÷数量。数量／寿命组合各有以场景时钟0为基准的出生序列，切段不会瞬间把全部旧粒子改造成新数量。
- 计算只依赖目标时间、出生时间、稳定槽位和随机种子，不依赖之前播放了几帧。倒放、跳播、暂停和导出同刻一致。
- 随机外观／候选点由槽位而非不断增长的世代号决定，避免循环边界因随机身份重置整体换一批位置。完整场景是否视觉闭合，仍取决于寿命／循环及其他动画是否匹配；不承诺任意时序组合自动无缝。
- 支持前一循环的出生预热；负出生时刻按场景循环读取当时来源和变换。全局显隐／显示时段仍控制整个发射器；隐藏出生阶段不创建有效粒子。

## 统一范围与交互

发射和显示均使用现有`renderMaskFields`，显示：无／图形／图片／场景对象。图形支持同一多图形集合与编辑器；图片／对象支持透明度或亮度；反相、跟随、来源处理、来源显示及临时预览共用，不复制一套粒子表单。

原“运动范围”在UI改名“显示范围”，数据仍使用`particle.motionRange`，保持稳定字段。范围参数全部No，没有独立时序按钮。来源自身动画／时序仍生效。

默认几何／图片范围从发射器本地0,0开始，使用`follow:true, followMatrix:[1,0,0,1,0,0]`进入统一变换链。场景对象来源保持自己的世界位置，不能再叠加发射器跟随。解除跟随会把当前位置烘入`geometryMatrix`，不让范围跳回原点；重新绑定以当前变换为基准。

旧粒子范围的follow字段过去被忽略；本批按真实跟随语义求值，不保留一套“字段false但仍隐式跟随”的永久分支。

### 发射范围

每个出生身份只有一个确定性候选点；按该点灰度接受出生。白色全部接受，灰色按权重接受，黑色不出生。没有随机重试失败后落到中心的兜底。

非反相的图形／图片在自己的范围内取候选；对象在完整隔离结果的范围内取候选。空白边距、图形间隙或低亮度都可能减少实际数量。反相在发射器自身的有限区域内定义。

对象分布严格取出生时刻的完整处理结果；不拿当前帧来源重新安置旧粒子。出生分布使用Full工作采样，不让Draft预览改变出生身份／接受结果。显式`sourceQuality`仍有效，属于用户保存的来源设置。

### 显示范围

按粒子当前世界坐标的中心取灰度，乘入透明度。不会改变轨迹，不是碰撞边界，也不是逐像素裁切。中心在范围内时，精灵跨出边界的部分仍保留；灰度128得到约50%透明度。

范围可跟随当前发射器或固定画布，与出生基准独立。无显示范围时不额外限制。范围预览显示当前分布，不是所有历史出生位置的叠加。

## 四层落点与资源

1. **定义／状态**：`49-mask-contract`共享几何包含测试、亮度×Alpha及引用环校验；`EditorVNextMaskState`开放粒子四类来源，仍走相同portable／ID重映射／跟随写入。
2. **Inspector／画布**：共用`renderMaskFields`与绿色编辑器。粒子范围用统一placementMatrix，支持多图形、渐进坐标、文件导入、提取方式和来源档位；内部粒子实体不作为默认公开来源，已引用私有依赖保留ID显示。预览扩展到两个粒子scope，Esc／返回不写工程。
3. **Runtime**：`52-mask-sampler`用于点／灰度消费；`74-particle-births`生成候选出生时刻；`75-particle-renderer`缓存出生快照并共享当前精灵。`80-scene-renderer`管理每Player会话及finally清理，不使用跨项目全局出生表。
4. **测试／交付**：见下节。元素素材入库、重定位和实例化均复用MaskState的detach／translate，不能另写粒子范围坐标。引用闭包同时携带范围图片、对象及其依赖；项目冲突ID重连已验证。

公共Player以`modules.particles.birthRanges=1`声明新语义。含粒子的交付遇到旧Player明确提示更新，不静默按旧“所有粒子跟随当前发射器”播放。源码、分发和内联镜像同步。

## 取样、缓存和边界

- 几何使用与正式路径相同的nonzero包含语义，集合固定合并；点消费不逐个读取整图像素，也不为每个图形申请全幅Canvas。
- 图片使用正式素材帧解析，复用原始分辨率的单通道灰度数据并双线性取样，支持序列在出生时选帧。单通道缓存8MiB，单图最多16MP；来源图片／对象均使用相同亮度系数。
- 静态完整对象可复用其隔离结果及灰度；动态对象首次出生只读该候选点，需要批量显示取样时才共享整幅灰度读回。动态完整来源本身仍可能昂贵。
- 每Player最多8192条出生记录（包含未接受的出生），候选最多16384／次，存活最多4096／次；超出明确报错，不偷偷删效果或丢粒子。缓存淘汰只影响重算成本，不影响固定时间结果。
- 数量／寿命只支持Step；明确拒绝对其使用Linear出生时序。其他基础对象变换的Linear仍可在出生时求值，不冻结整个对象时序。
- 场景滤镜GPU不会自动加速历史出生取样。历史来源当前走确定的CPU路径；本批没有新增GPU粒子／蒙版算法，后续若改用GPU须验证出生时刻和嵌套会话恢复。

## 性能实测：冷启动不能忽略

脚本：`tests/browser/v4-particle-range-performance.mjs`。CPU／Canvas2D；40个粒子，寿命2秒；对象来源占画布宽高各40%，含bob、描边、阈值和杂色。首次直接定位1秒，再以1/120秒推进20次；后续仅新增3条出生记录。下表为本机诊断，不是发布性能预算或跨设备保证。

| 画布 | 来源处理 | 首次耗时 | 后续P95 |
| --- | --- | ---: | ---: |
| 320×180 | 默认几何 | 28.5ms | 2.8ms |
| 320×180 | 完整对象 | 583.4ms | 13.5ms |
| 320×180 | 对象不含采样 | 162.8ms | 5.4ms |
| 960×540 | 默认几何 | 8.7ms | 1.3ms |
| 960×540 | 完整对象 | 878.2ms | 23.0ms |
| 960×540 | 对象不含采样 | 176.1ms | 6.1ms |
| 1920×1080 | 默认几何 | 8.0ms | 1.3ms |
| 1920×1080 | 完整对象 | 2232.4ms | 53.4ms |
| 1920×1080 | 对象不含采样 | 252.6ms | 7.3ms |

完整／不含采样均首次捕获40个历史来源状态；L档累计约13.66MP来源表面。S几何首项包含启动成本，不能根据其高于M／L推断画布越大越快。结果也不覆盖所有效果、数量或动态分布。

**结论：出生缓存解决稳定播放的重复计算，没有消除冷启动。** 打开工程、冷跳播或编辑导致Player重建后，重效果来源仍可能出现明显等待；提高数量会放大成本。需要精确完整Alpha时保留完整；不需要来源采样影响分布时，可显式选择“不含采样”，或减少数量／来源尺寸、使用静态图片／几何。不能为追求数字好看自动降级。

全量性能收口仍在U6。U3已记录的通用预览压力夹具未通过项未被本批覆盖或宣称修复。
