# 对象采样 GPU 最小试点：接线前审计

2026-10-25 状态更新：本文保留接线前审计历史。现已完成受限的正式编辑器对象阈值试点；下文“未接入／返回null”仅描述原型时状态。当前能力和限制以 [对象试点合同](V4_GPU_OBJECT_PILOT_CONTRACT_2026-10-25.md) 为准。复杂加样前处理发现CPU基准首帧不一致，未纳入准入，见 [阻塞记录](V4_GPU_OBJECT_PREFIX_BLOCKER_2026-10-25.md)。

日期：2026-10-24。状态：**先做独立对象胶囊原型；未改正式对象绘制入口，不增加对象GPU能力声明。**

## 可以直接复用

- `69a-scene-gpu-executor.js`的阈值Shader、严格JS亮度临界值表、Alpha解码及预乘舍入、整数坐标／Canvas原生坐标校准、初始化／GL错误回退。
- `30-frame-state.js`已经求值的对象参数、对象效果和采样格控制器。不可在GPU层重新读取Inspector或另设Step／Linear公式。
- `70-object-composer.js`已有世界坐标胶囊边界：真实图元／图片／文字／程序内容、附着内容、旋转／斜切、装饰留白都在胶囊边界内。不能只取元素W/H截断扩展内容。
- 现有Canvas内容绘制、全局对象蒙版、加样，以及最后的对象透明度×父组透明度、混合、滚动重复放置。

## 不能直接复用的语义

1. 场景执行器`plan`按scene作用域读取效果。对象应先通过`frame.effectValuesFor('object',id,...)`和controllerValuesFor求值，再传纯数据给内核；不能把对象时序伪装为scene时序重复求值。
2. 场景效果每张卡有独立范围蒙版、按卡重复采样。对象`sampling.apply`是采样格一次→同一低分辨率链→放大一次。多效果不能直接套场景的多卡计划，否则重复采样会改变画面。
3. 对象蒙版按胶囊世界bounds／元素跟随变换求值；场景范围蒙版按全画布求值。不能把对象蒙版交给场景范围分支。
4. 对象的mask／decorate／sample可调序；formation与最后的整体透明度／混合仍固定。不能让GPU试点悄悄重排。
5. 现有执行器尺寸变化会dispose并新建GL上下文。对象胶囊尺寸随对象、旋转、图元和装饰变化，逐对象照搬将导致严重初始化抖动。第8批同尺寸Workspace复用不能解决这一点。
6. 场景与对象的来源身份、范围坐标、统计、缓存键不同；不能让共享设备等同于共享最后输出缓存。

## 首轮原型边界

选择**阈值分色＋采样格**，而非一次实现全部对象效果。原因是它已有严格数值内核、无新增留白，不涉及图案生成或色板提取，同时较大对象CPU逐像素循环有明确优化空间。

只在测试中：

```text
真实对象／图元／图片／文字的Canvas绘制
→ 原有formation、mask、decorate（按原顺序，均CPU）
→ 已求值的单一threshold＋sampling-grid
→ 复用已有GPU内核
→ Canvas胶囊输出
→ 原有最后透明度／混合／放置
```

为复用场景执行器，仅在夹具建立无场景时序／无卡片蒙版的数值载体；其尺寸必须等于实际胶囊尺寸，effect/controller访问器返回已经求值的数据。这是测试适配，不写入作品、不成为正式对象协议。

原型预检：只支持sample位于最后、仅有threshold（或只有基础格）、alphaMode=keep、无卡内范围蒙版、无额外采样控制器。失败立即保持完整原CPU路径，不尝试逐卡GPU／CPU往返。采样不在末端等条件是后端试点边界，不是禁用产品功能或顺序。

独立原型不意味着这些条件已接入产品。Registry的`backendCapability(id,'object')`继续返回null；编辑器后端诊断仍说明对象为Canvas。

## 预计生产修改范围（原型通过后再实施）

1. `69a`先分离数值执行计划与scene求值适配，复用Shader而不是复制一套对象效果目录。
2. 将上下文／程序生命周期与尺寸相关纹理分开；共享设备支持对象尺寸变化时重建纹理而非上下文。坐标校准的尺寸映射与纹理预算需有界，不能按对象永久积累。
3. 增加Player／Workspace拥有的对象执行会话，明确来源scope＋owner身份、输出立即消费和错误状态；不逐对象建一个无限上下文池。
4. `70`在原sample阶段加预检和一次调用，其他阶段以及最终alpha／blend照旧。采样链任何不支持项都走原链，不部分吞掉或换顺序。
5. `69b`与现有Registry查询扩展object作用域，仅声明有实际路由和测试支持的项；新增对象实际后端、上传／输出边界、预算与原因统计。
6. 再补真实编辑器对象Inspector修改、撤销／重做、多个不同尺寸对象、重复滚动、粒子共享精灵、GPU对象与GPU场景组合、释放／失败完整回退。

本轮不修改`70/68`正式业务实现、Inspector、图样合同或参数输入，不开启对象GPU默认路线。涉及composer的下一批需继续小范围补丁，保护另一会话修改。

实验后补充：原型发现既有CPU对象胶囊会继承上次采样输出的`imageSmoothingEnabled=false`，导致相同图片首次与后续绘制不同。两条控制实验后确认；本批允许在`70`源内容绘制入口恢复默认true这一项最小正确性修复。不修改处理顺序或采样算法，不将此修复视作GPU正式接线。失败与控制报告保留在第9批记录。

## 原型验收

- 画质：不同来源与Alpha、扩展图元、旋转／斜切、跟随／反相蒙版、CPU装饰、父组透明度与混合；同一已求值时间及seek前后对照。临界阈值与动态不再发明公式。
- 性能：CPU完整对象胶囊与GPU前处理＋上传＋内核＋Canvas输出整体计时；首次初始化另列，预热与样本数明确。GPU调用时间不是设备GPU时间。
- 边界：不支持的效果或顺序在分配／上传前拒绝；不得以缩小参数范围通过测试。
- 资源：每例释放；同尺寸热帧无持续分配；同时说明不同尺寸会重建的现有缺陷。
- 必须区分“独立原型通过”和“正式编辑器对象已加速”；原型数据不替代真实编辑器验收。
