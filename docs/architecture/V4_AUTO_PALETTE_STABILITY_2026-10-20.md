# 自动取色精度与稳定性：10-20续批

意图：修复已有减色流程，沿用 Inspector 的单选和小按钮；不重新设计面板。用户应能调整减色程度，而不是在移动对象时无意改变全场色调。本合同接续 [颜色映射首批](V4_COLOR_MAP_CRT_BANDS_2026-10-20.md)。

## 四层落点

| 层 | 落点 | 本轮变化 |
| --- | --- | --- |
| Registry／状态 | `effect-registry-vnext.js`、`vnext-effect-state.js` | 增加内部派生数据 `extracted`，默认null；严格校验、深复制；不直接生成参数输入框 |
| Inspector | `classic-v4-color-map-control.js`、`classic-v4-inspector-controller.js` | 自动提取的色数右侧增加“重新提取”；首次启用、更改色数、切回自动提取时提取并保存；明确按钮复用，无额外面板 |
| Runtime | `68-sampling-effects.js`；frame／对象／场景管线的局部取色回调 | 全图有界统计、确定性 Median Cut、避免空分组、完整RGB最近色与缓存；有有效extracted时不再从每帧来源重取色 |
| 验证 | `v4-auto-palette-stability.mjs`及browser同名夹具，接入verify-v4 | 窄色域六档、全图统计、近似格精度对照、启用／刷新／保存／撤销／时序／隔离 |

## 1. 取色统计

旧实现上限是“最先遇到的65536种颜色”：高色数照片会拒收后续新颜色，并保留先入颜色的频数，产生空间偏差。现改为从整幅输入的像素范围均匀选取最多65536个样本；样本保留完整RGB和频数。小图逐像素统计，大图为有界统计，不声称捕获每一种小面积颜色。

相同直方图在切分前按RGB排序；切分中遇到通道同值亦按RGB破平局。像素排列不同不应改变相同统计的分组结果。主色占比过高时，中位分割索引仍限制在有效内部位置，防止空盒和NaN代表色。

最大颜色数仍是上限，不保证对原本只有4种颜色的图生成16种颜色，也不保证受后续阈值／单色效果处理后保留全部代表色。

## 2. RGB5只作安全加速，不再作为精度上限

旧版每个8×8×8 RGB立方格只查同一个代表色：同格里的64种真实颜色即便提取出64个代表色，也可能全部显示成1色。

新版按需建立32768格索引及状态表。若能证明整格内同一个代表色始终最近，则使用快速结果；若格与色板Voronoi边界相交，则以来源原始RGB计算精确最近色，复用最多4096项精确颜色缓存。判断边界采用距离差的保守上界，不只检查格中心或假设某些角点相同。

缓存表与精确缓存均受预算控制，仍最多保留12份映射／渐变条目，不创建1677万项全RGB表。缓存只加速，不改变输出；两万组确定随机颜色已与完整遍历色板的参考计算逐一对照。

## 3. 固定色板的状态合同

```js
effects.sample['color-map'].extracted = {
  colors: 16,                 // 当次请求的最大颜色数，非实际色数
  entries: [[r,g,b], ...]      // 1～colors个代表色，RGB整数0～255
};
```

场景同字段位于 `sceneEffects.sample['color-map']`。当前 `colors` 与 `extracted.colors` 一致才使用该色板；命名调色板和渐变映射不使用它，但切换模式不清除它。

- **首次启用自动提取**：从当前时刻、对应处理阶段的Full输入提取并存入工程，随后播放、移动、裁切和背景变化均沿用该色板。
- **修改最大颜色数**：对当前输入重新提取一次，并与新色数一起单次提交，不在每帧重复提取。
- **重新提取**：显式替换代表色；遵守现有效果轨Step写入语义，有时序时只写当前段，无时序时写基础值。支持撤销、重做、保存重开。
- **效果启用开关**：仍是全局启用，不因为时序已亮而变成当前段开关；启用和初次色板数据一次提交。
- **旧工程／外部生成的简写配置**：缺少extracted时仍能运行，维持根据输入提取的回退行为。不在读取或普通绘制中悄悄修改工程。用户点击一次“重新提取”或改变色数后，才得到持久固定结果；重新启用尚未固定的效果也会提取。
- **提取位置**：不是屏幕截图；对象取自己的处理阶段输入，不包含背景／其他对象／场景滤镜。场景取该场景滤镜前的合成输入。两者都包含既有前置处理及当前采样格，蒙版仍遵循原效果管线。

## 4. 提取事务与性能边界

用临时Player和当前已解析素材，在请求时刻跑真实管线。局部回调只捕获目标scope／owner，禁用过渡递归和实验场景GPU链，Full取样；不切换正式Player，不写全局“当前色板”，不把临时画布当素材入库。

结果先校验再提交。素材解析期间工程revision变化、当前效果时段／时序写入目标变化时拒绝旧结果；失败不部分启用／写入。提取时提供禁用状态，已有工程内容不作为乐观占位修改。临时Player和画布在finally释放。

保存后的工程与交付直接携带最多64个RGB代表色，不要求重新安装服务或运行模型。颜色映射本身仍需要逐像素替换；固定色板避免的是每帧直方图／分组／重建映射，不意味着完整图像处理零成本。精确边界区域比旧近似查表多计算，换来不会过早合色；未承诺所有尺寸的固定帧率。

## 验收记录

真实浏览器中，原RGB5同格样本六档实际输出2／4／8／16／32／64色；对象位置与场景背景改变后固定色板和对象采样结果保持一致；刷新确实替换色板，单步撤销／重做恢复；保存重新读取得到相同画面；对象提取不混入场景绿色背景；Step只写当前效果轨；异步切工程前检查通过。

同步跑既有效果状态、术语、参数计划、Runtime smoke、10-20渐变／CRT合同及浏览器、对象效果和10-19效果回归。证据截图 `docs/design/evidence/effect-adjustments-2026-10-20/fixed-auto-palette.png` 实际查看，修正按钮换行；未进行独立评分、全量verify-v4或Tauri打包。
