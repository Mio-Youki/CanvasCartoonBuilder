## 1. 目标与已确认边界

让用户可以把内容放入作品、沿路径生成图形、调整外观，并把值得复用的成果带到其他工程；不要求用户理解实现代码、依赖图或插件注册表。

以下三条已确认，后续实现不能自行反转：

1. **项目素材栏保存可复用定义，结构树保存画布实例。** 不自动镜像全部场景对象；明确“收入素材库”后才形成元素素材。相同来源可以生成多个独立实例。
2. **共享采用显式发布的副本。** 工程修改不自动传播到共享库或其他工程；通过明确的更新动作发布，取用时复制完整依赖到当前工程。
3. **图样并行读取同一载体路径。** 图样不修改载体，也不读取其他图样输出；调序仅控制视觉覆盖，不形成图样计算链。

已对齐的下一步方向：复用R1～R4底层；先补元素素材定义与引用闭包，再收口项目／共享入口，明确生命周期，最后调整图样。通用算法插件暂缓。图样面板、删除细则等尚未确认的内容，必须通过下方决策门，不能当成用户已经批准的界面。

## 2. 概念与实现分离

| 用户概念 | 拟定职责 | 不应混入 |
| --- | --- | --- |
| 素材：位图／序列／元素 | 可反复取用的内容；元素可含图元、程序实现、图样及对象效果 | 当前工程全部实例的实时镜像 |
| 图样 | 基于路径生成附加图形／排布，也可以通过默认载体新建 | 任意画面滤镜、图样递归计算链 |
| 加样／采样 | 处理已有对象或场景的图像 | 随意修改其他对象及自身所属阶段 |
| 属性 | 对象自身状态、基础几何与受控路径处理 | 仅因能挂输入框就宣称支持新算法 |
| 项目／共享 | 保存范围，不是新的资源类型 | 自动联网共享、隐式跨工程实时链接 |

“程序构件”是实现方式，不是一级资源类型：独立雨幕属于元素素材；路径控制的雨幕可属于图样，但需先检查能否复用粒子能力。最终导入分类依据声明的功能合同，而非仅凭扩展名或是否含JS猜测。

## 5. RC1／RC2需要形成的最小合同

不是现在预定一套巨型新Schema，而是先用实际案例收口必要字段和变更命令：

- 素材定义、工程实例、共享发布版本具有不同身份；创建实例不修改源定义，修改源定义是否影响既有实例须明确，不能暗中引入组件实时联动。
- 保存基础全局值，舍去参数覆层、显示时段和临时编辑状态；全局循环动态按D1确认处理。预览不能悄悄采集当前时段值来填基础参数。
- 位图／序列保留已确认的非破坏预处理与Alpha关系，不能通过入库丢失恢复基底。
- 元素依赖需包括实际使用的位图、图样、模块、被引用的来源对象，以及未来已支持的自定义效果；未知类型明确拒绝或报告，不伪装支持。
- 外部对象引用转为素材内部闭包并重映射ID，不依赖原场景对象编号；检查循环与缺失，不无条件复制整个工程。
- 跨工程文件和实现冲突不覆盖已有内容；所有异步准备校验工程身份／revision，完成后一次写入并可撤销。
- 不因收藏或预览继承授信，不在文件夹扫描、缩略图生成或hover时自动执行未知代码。
- 物理字节去重、目录Vault、自动恢复上次工程不是本合同的必要前提；避免以“必须重写存储”阻塞用户闭环。

最小验收案例：处理过的位图及Alpha恢复基底、多帧素材、带图样的矢量元素、带公开参数的程序元素、引用其他对象作蒙版／排布来源的元素。组／粒子是否加入首批以D1为准；未做的类别保持明确禁用或提示。

## 6. 各阶段统一四层落点与门禁

每批改动先写一份小清单，然后实现，不进行跨全文件的无界替换：

| 层 | 每批必须写明 |
| --- | --- |
| 数据／Registry | 保存字段、身份、依赖、默认值、约束、是否升级；没有改动也注明 |
| UI／命令 | 真实入口、选择上下文、反馈、取消、确认、错误、撤销；以及对另一前端会话的交接 |
| Runtime／Resolver／Host | 求值、资源加载、边界、缓存、代码授信、存储与交付；不适用则注明 |
| 验证 | 静态合同、失败无半成品、真实浏览器操作、固定时间像素、性能／存储边界 |

小批默认顺序：语法／静态合同 → 定向状态测试 → Runtime smoke（有渲染变化时）→ 真实浏览器流程。阶段完成再跑对应整组回归；完整verify-v4及Tauri文件宿主验收放在明确的集成检查点，不要求每个小输入变动重跑全项目，也不以浏览器通过冒称桌面文件系统通过。

UI视觉只沿用现有设计方向，按oil-ui-pro做存量流程与状态走查；未获批准不重新制作主题、图标或全局排版。手工文件修改继续使用apply_patch，禁止用默认编码的PowerShell整文件读写重演事故。

## 7. 效果DIY的独立验收计划

RC7／RC8各自再按“合同→单样例→组合→性能→界面与交付”分批，可跨多个工作周期，不要求一次完成所有加样／采样。

共用测试素材优先复用项目已有资产，缺少时建立小型可生成夹具，不引入大模型／大型依赖作为强制前提。建议覆盖透明几何、细线／文字、含半透明边缘的图像、彩色照片、运动内容；文件授权与是否提交仓库单独检查。

| 门禁 | 要证明什么 |
| --- | --- |
| 中性与关闭 | 零强度／关闭时直通，无残留状态或额外无效像素遍 |
| 确定性 | 固定输入、时间、参数、种子结果一致；不同Player和工程不污染 |
| 视觉目标 | 预先给出参考与可观察特征，用户／人工审阅；“没有报错”不能替代效果质量 |
| Alpha与范围 | 不污染透明背景，外扩有界，声明的保边／内部行为成立 |
| 顺序与组合 | 蒙版／加样／采样阶段关系明确，卡片顺序等于实际处理，组合不静默失效 |
| 性能与释放 | S／M／L尺寸的冷启动、稳定P95、像素遍／离屏量、缓存上限、关闭后释放；CPU／GPU分开说明 |
| 编辑与交付 | 参数可实际改变画面，撤销恢复，工程重开和HTML一致；未知实现明确报告 |

门槛数值应在对应实验前结合现有性能合同和硬件基线确定，不先写一个未经测量的全画布实时承诺。任意代码不能靠“声明预算”获得强制执行时限；需要另行设计隔离或准入，不伪装已解决。
