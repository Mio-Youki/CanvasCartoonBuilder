# v4 与 Legacy 差异白名单

> 本文件是唯一允许差异入口。未列出的用户可观察差异均视为回归。新增条目必须由产品负责人明确批准。

| ID | 已批准差异 | 允许范围 | 不允许范围 | 状态 |
|---|---|---|---|---|
| `D-001` | v4 Scene 持久格式 | v4 会话保存 `.tosampool.json`；Legacy 会话继续保存 JS | 改变同一操作的可见结果；后台双写 | approved |
| `D-002` | 对象处理阶段 | `mask / decorate / sample` 为显式大阶段并可调序 | 阶段内部隐藏级联；改变未调序时的 Legacy 对象样式结果 | approved |
| `D-003` | 取消“局部 FX”存储/名称 | v4 使用带独立蒙版的场景效果表达区域后处理 | 自动改成对象加样；声称继承对象 z | approved |
| `D-004` | 程序代码策略 | Legacy 会话执行旧代码；v4 使用注册 builtin 或用户确认的冻结素材 | 把任意代码写进 v4 JSON；静默栅格化 | approved |
| `D-005` | 性能内部实现 | 缓存、调度、离屏表面、质量档可替换 | 降低 Full/导出质量；改变画面；修改交互语义 | approved |

## 优化提案模板

每项优化在实施前新增一条决策记录，至少包含：Legacy 当前行为与测试、问题、可观察差异、数据/兼容影响、性能前后数据、视觉对照、旧作品影响、回滚方法和产品负责人批准。“代码更合理”“v4 更现代”“实现更简单”都不是批准理由。
