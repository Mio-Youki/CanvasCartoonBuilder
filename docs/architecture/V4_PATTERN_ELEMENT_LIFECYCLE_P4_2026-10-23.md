# RC5-P4：元素携带图样、私有来源生命周期与名称元数据

2026-10-23。已有界面加功能，沿用原卡片与名称编辑习惯，不换视觉。用户可以取用带图样的元素、修改资源名字，不需要维护实现依赖，也不会因改名失去图片或程序来源。

## 图样随元素取用

- 图样几何参数已内嵌在元素自身的路径配置中，属于可编辑的声明数据，而不是另一张渲染后的图片。
- 元素入库、从共享／文件包导入、从元素素材放置时，遍历根对象、组成员及私有引用来源，为已有图样补齐项目卡片。已有同身份预设不被隐式覆盖，画布仍使用元素自身保存的参数。
- 刻度、嵌套、元素排布、箭头、括号复用同一个资源层与生成器，不创建第二套目录。自定义声明式图样携带定义及几何快照；同ID同版本的实现冲突依然拒绝，不能当作参数覆盖。
- 原生图样可从路径配置恢复目录；图片／Module等实际依赖仍经过原有引用闭包与信任流程。依赖不存在、循环、预算或实现冲突时不提交半份工程。
- 依附对象、组的内容保存在元素预设内部；取用时重映射成私有来源，不额外创建可见素材卡。先前私有图片／Module闭包仍复用原接口，本批不增加模型或外部服务。

## 来源生命周期

- 停用图样不清空来源，恢复时仍可使用；移除图样、替换排布来源、删除图元或载体后，仅清理不可达的私有场景来源。
- 从普通可见对象以及场景效果／时序引用出发检查可达性，保留共享引用、组成员和休眠配置里的引用。不会删除素材库位图、项目图样预设、Module定义或用户普通对象。
- 删除仍被引用的可见来源时，先保存独立的私有可编辑闭包并转接引用，包含原参数、基础动态及现有时序；不是冻结成图片。组来源先保护，再执行原有解组语义。
- 清理发生在结构操作／来源更换时，不在播放帧中运行。新增载体尚未插入场景的绘制暂存期不执行全局清理，避免误删其他待提交载体的来源。
- 上述变化跟随原历史事务；撤销恢复图样及其私有来源。无显式物理素材清理。

## 素材／图样名称

| 范围 | 操作与影响 |
| --- | --- |
| 项目位图／序列／元素／图样 | 双击卡片名称改名；修改现有name，支持撤销，不重命名ID、不改引用、不改已经放置对象的名字 |
| 共享素材／我的图样 | 双击名称改名，只更新共享发布名称，保持发布ID、内容hash与root；CAS版本递增，持久保存，不反向修改项目副本 |
| 项目回传共享 | 仍需主动点击“更新共享”，同时回传项目当前名称与内容；不是名字一改就自动同步 |
| 自带基础图样 | 名称只读，不改变内置登记 |

名称为1～120字符，不能是空白或含控制字符。允许不同项目资源使用相同名字；识别依赖稳定ID。共享现有同名避让规则保留。

图样项目别名同时用于结构树已应用条目和Inspector标题，参数键与生成器ID不变。单击卡片依旧执行原选择／定位操作，双击由共享名称组件跨卡片刷新识别，不因首击重建DOM失效。

元素预设新增可选`patternNames: { [generatorId]: displayName }`，仅保存实际携带图样的名称别名。不存另一份参数、不存工程卡片ID，不参与引用重映射或Runtime绘制；导出结果会连同工程资源目录剥离。它使共享元素中的图样别名在新项目仍能恢复；已有项目卡片名字优先，不被隐式导入覆盖。

## 四层落点与验收

- 资源／合同：`v4-resource-core.collectElementPatterns`、`v4-element-presets`名称元数据、共享库`rename`及稳定身份。
- 界面：统一`classic-v4-resource-name`绑定，项目与共享卡片复用；图元结构树与Inspector读取同一个项目别名。
- 生命周期：`v4-element-references.prunePrivate`统一检查；图样替换／移除、图元及对象删除调用，沿用共享蒙版引用接口。
- 测试：`tests/v4-pattern-element-lifecycle-contract.mjs`与真实浏览器`tests/browser/v4-resource-renaming-p4.mjs`；既有路径预设、图样卡、P3排序、元素依赖、组／粒子、项目交接及素材共享回归。

已通过：六类真实双击、稳定ID与撤销、共享独立改名与显式回传、自带只读、改名后的结构／Inspector同步、跨项目元素携带图样和别名、来源停用／共享引用／替换／删除、工程及共享往返、缺依赖原子失败。截图`tests/artifacts/rc5-p4-resource-names/page.png`已查看；局部自检，无独立视觉评分。未做全量verify-v4、Tauri封装及长期性能测试。
