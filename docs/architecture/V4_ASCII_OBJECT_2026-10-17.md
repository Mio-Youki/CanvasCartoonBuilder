# 对象ASCII映射：接线、边界与验收

## 四层落点

| 层 | 修改 |
| --- | --- |
| Registry／Agent manifest | ascii-mapping增加object作用域与ready状态，对象成本C；参数沿用场景版，全部Step。particleBake声明shared-frame。 |
| Inspector／效果容器 | 由Registry生成对象采样卡及左侧效果项，不新建另一套面板。字体／混合／原图背景／时序仍走共享写入。 |
| Runtime | sampling.apply先完成基础格与已有采样，恢复完整胶囊尺寸后调用ascii.apply；禁止在降分辨率applyFull内再次放大字符单元。正式分发与内联同步。 |
| 验收 | v4-ascii-object.mjs加入verify-v4：矩形、多图元、图片、文字、程序对象；采样格等价、旋转、透明度、阶段调序、Step、图集LRU／释放、粒子共享、Inspector、撤销、项目与HTML。 |

## 几何与透明边界

- 沿用既有对象采样的**轴对齐世界空间胶囊**，不是把字符另建成跟随旋转的矢量实体。对象本身的旋转／缩放先绘入胶囊，再进行ASCII。
- 格锚点为对象worldMatrix原点向下取整后的坐标。对能容纳一个完整单元的方向，胶囊起点扩至其前方最近的格边界，减少投影／图元扩边改变最小边界时的相位跳变。小数字形比例下仍存在整数backing舍入，不能宣称任意仿射变换完全无采样跳变。
- 单元大于对象胶囊的方向不做格长级的空白扩边，避免极大相对尺寸造成巨量离屏分配。没有限制用户参数或偷改采样格。
- 整字按单元代表Alpha绘制，不逐像素截回原图Alpha。字符可能越出原轮廓，但不会形成不透明整面背景。需要严格裁边时，把对象蒙版放在采样之后。选择框仍代表原对象几何，不扩大成ASCII字形外框。
- 原图背景只保留当前对象在ASCII之前的胶囊内容，不读取下面其他对象或整场景。混合模式只作用该对象内部；最终对象混合与透明度继续在胶囊合成后应用。
- mask／decorate／sample可继续调序。ASCII固定是sample组末端，不新增独立处理阶段。

## 缓存与性能边界

CPU字形图集仍最多12张。每个SurfacePool只用一个共享ASCII WebGL上下文，GPU字形纹理增加LRU：最多4张近期图集、总预算4MiB（单张超预算可单独保留，仍受纹理尺寸能力限制）。固定基础纹理保留到pool.clear；被淘汰的额外纹理即时释放，clear释放所有纹理与分析资源。

两套字符交替20次实测仅上传2次；7套字符触发淘汰时实测最多6个活跃纹理（包含颜色／索引，不开边缘分析），清理后0。单一图集20帧仍只上传一次，不增加逐帧字体烘焙。

粒子源沿用每帧共享精灵：30个粒子只生成一份ASCII精灵；多帧源仍按既有帧数生成，不按粒子数量重复ASCII。大对象、多对象、边缘分析仍可昂贵，不能以“局部”承诺固定帧率。测试含640×360上1／8个120×96对象的预热墙钟测量，不是1080p多效果保证。

## 交付边界

对象定向检查与完整verify-v4均通过；另行扩充了透明度、格点锚点、GPU淘汰释放、粒子共享与多对象测量检查并通过。构建／内联／manifest一致性另行核验。

本机Edge参考：640×360画布，关闭边缘分析、两套字符交替，120×96对象预热后10帧墙钟；Auto单对象中位5.3ms、8对象59.4ms，显式CPU单对象4.8ms、8对象69.9ms。本次CPU对照没有稳定优势，故**保留Auto策略，不引入未验证的面积阈值**。该测量含离屏绘制／取样／合成，不是纯字符循环耗时，不代表最终桌面包性能。多对象成本确实可累加，缓存解决的是字形反复上传，不等于消除全部读回／合成成本。

无需迁移场景或新建数据格式；保存、时序、原图背景及字体图集仍由共用机制处理。对象定向浏览器检查通过；未重打Tauri安装包，不能将浏览器验证称为正式桌面包资源验收。
