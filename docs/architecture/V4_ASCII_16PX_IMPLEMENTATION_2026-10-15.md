# 寒蝉16px＋16×16混合图集：实现与交接

> 历史方案：当前默认已恢复8px混合，16px作为整套可选字体，见[V4_ASCII_PIXEL_FONT_OPTIONS_2026-10-15.md](V4_ASCII_PIXEL_FONT_OPTIONS_2026-10-15.md)。下述数据是当时16px混合验收，不代表当前默认。

## 当前行为

`font=builtin`内部格现为16×16。原14个内置符号／方向字符最近邻2倍复制，归一化Alpha覆盖率精确不变；扩展字符使用寒蝉点阵体16px、16px原生em、字体公共基线居中排放。半宽拉丁字不横向撑满，只有过长字素按advance缩小以防溢出。不按单字紧框拉伸，不加粗或重算原位图。

合并为一张图集后按最终Alpha一起计算density与LUT。新增“界”的覆盖率可以高于内置@，是正确的候选排序；原内置字符彼此的覆盖率与相对顺序不变。亮度映射候选增加可以合理改变画面，不承诺扩展前后完整画面一样。

## 字体来源与许可

作者当前仓库README介绍16px，但实际Version 2.400 ZIP仅含7px；早期文件列表亦未找到16px原件。没有把7px放大当成16px。

实际使用字体收藏仓库的未修改16px文件，其内嵌family为“寒蝉点阵体 16px”、Regular、Version 1.000。镜像Git blob、原始SHA-256、版权及作者许可保留于[字体说明](../../assets/fonts/ChillBitmap16-README.md)。它没有与作者网站原件逐字节比对，不能声称拥有官方发布校验和；来源与此边界明确记录。

字体内嵌声明为OFL1.1／GPL2或更新＋GNU Font Embedding Exception双许可。随资源保留作者完整声明，不将字体重新标为编辑器MIT代码。未改字体二进制、未做字形子集化／改名；浏览器FontFace仅使用私有family别名。

原文件12,636,508字节；gzip 2,867,224字节；包含Base64及来源信息的懒加载JS为3,823,701字节。包装后可恢复完全相同的TTF（构建检查SHA-256），不是新的字体格式或改造字库。仅编辑器第一次确实需要扩展字符时加载／解压一次；默认10符号＋方向不触发字体下载。没有安装系统字体。

## 载入／编辑边界

- `EditorClassicV4AsciiControl.ensureBuiltinFont(nextValues)`按需异步加载资源、解压、FontFace.load后注册，再通知Runtime字体已就绪。空闲／载入／就绪／失败状态可诊断。
- Runtime本身不请求字体。扩展字符未烘焙且未注册字体时会明确报错，不再偷偷用monospace。Agent／独立Runtime仍应给自定义字符提供glyphAtlas。
- Inspector修改字符／方向字符时先等待载入，再调用原同步`preparePatch`，图集和字符同批写入。载入期间禁用该输入；失败显示原生输入校验，不写入伪图集。项目切换或控件已拆除则丢弃迟到写入。
- 默认字体选择也等待就绪；主动选择系统／导入字体仍采用之前的整套原生字体路径。
- 已保存的8×8／旧字体图集继续按原掩码播放，不静默迁移。修改字符集或切换字体可重建为新图集。
- 字体覆盖之外的罕见字素不保证外观；常规中文／英文已验。内部精度16不等于8像素输出单元里中文也清晰，建议结合相对尺寸选择12／16以上。

## 性能与导出

统一图集、原12项缓存、每pool一张当前字形纹理不变。默认14字形3584字节原始Alpha，增加A/a/中/界后4608字节；相比8px阶段各为4倍，但远小于整套字体。连续20帧字体绘制／测量0次、字形纹理上传1次。

工程／HTML只带所用灰度图集，不携带懒加载字体JS／完整TTF。解压字体是编辑时开销，不是每帧工作。首次载入的网络／磁盘与解压耗时不应误报为持续播放开销。本轮不重新承诺FPS。

## 四层落点

| 层 | 改动 |
| --- | --- |
| Registry | 稳定ID／默认字符／用户参数不变 |
| Inspector | `classic-v4-ascii-control.js`增加ensureBuiltinFont与状态；字符／方向写入改为等字体后同批提交；默认字体提示说明16格 |
| Runtime | `68b-ascii-mapping.js`内置掩码2倍复制、16格扩展；缺字体明确拒绝；分发与内联镜像均重建 |
| 测试 | 默认字体传输完整性加入verify-v4；glyph fixture测试2倍复制／覆盖率／原输出／排序／缓存／失败；原ASCII与CPU／GPU夹具回归；真实Tauri --glyphs |

**并行UI会话须同步**：字符／方向编辑入口不能再直接假定`preparePatch`一定立即可用，先`await ensureBuiltinFont(合并后的值)`，检查目标项目／控件仍有效，再同批写入。必须托管`assets/fonts/ChillBitmap16-default.js`及两份许可／来源文件。旧Tauri白名单仍为Legacy，不代表正式v4安装包已包含此资源；本轮桌面测试为已有exe临时加载最新v4。

## 验证与对照

- 浏览器：14个原字形逐像素2×复制、覆盖率相等；默认字符在8／12／16输出单元与冻结8px参考逐像素相同。
- 扩展A/a/中/界不为空；新增宽字不改变既有字形；全部density／256项LUT按最终Alpha验证。
- 项目打包／恢复、真实Inspector输入、撤销、自包含HTML、未安装字体但已带图集的播放通过；额外断言HTML不含整套字体加载器。
- 模拟FontFace载入失败：状态为failed，Runtime仍拒绝未烘焙扩展字符，不静默改用系统字体。
- Edge与真实Tauri WebView的这4个扩展字符测得相同覆盖率；20帧缓存检查均通过，不作所有硬件／字素逐位一致的泛化保证。
- 状态合同、Runtime smoke、原ASCII浏览器、40组CPU参考、22组GPU精度／回退／释放均通过。统一verify-v4已加入字体校验及新流程。
