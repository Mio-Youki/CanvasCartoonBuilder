# RC1：元素素材最小合同与现状审计

状态：RC1合同与只读现状审计完成；后续[RC2-a独立元素数据闭环](V4_ELEMENT_PRESETS_RC2A_2026-10-21.md)及[RC2-b依赖闭包](V4_ELEMENT_PRESET_DEPENDENCIES_RC2B_2026-10-21.md)已实现，RC2-c外部来源及用户面板尚待完成。下文现状表保留RC1审计时点，不作为当前功能描述。2026-10-21用户已确认D1三项取舍。隶属[产品收口计划](V4_RESOURCE_PRODUCT_CONSOLIDATION_PLAN_2026-10-21.md)。

## 1. 本轮已经确认的范围

| 决策 | 用户结论 | 实施含义 |
| --- | --- | --- |
| D1-a 首批对象 | 普通元素＋程序元素；组与粒子后续处理 | 首批不支持将组／粒子发射器作为素材根节点；依赖中遇到需要组／粒子语义的情况也不能伪装支持 |
| D1-b 动态 | 保留基础循环动态 | 保存全局anim、图元anim、图样／效果的基础动态设置；舍去对象／效果／动态的时序覆层和显示时段 |
| D1-c 父级 | 只保存自身局部属性 | 不继承父组变换、透明度、动态、蒙版或其他处理，不附带无关兄弟；从组中入库的结果不承诺与原完整场景外观相同 |

普通元素首批目标包括图片、文字、矢量和原生几何，以及当前Runtime支持的内置构件；“普通元素”不表示支持未知type。程序元素必须携带对应实现和声明，不用默认参数替换当前实例参数。

## 2. 定义、实例、共享发布三者分离

1. **元素素材定义**：一次显式入库得到的基础参数与可编辑结构快照，以及完整依赖。它不是整个Scene，不包含timeline、background、sceneEffects或Workspace状态。
2. **画布实例**：由定义创建的独立对象和必要内部来源；拥有新的对象身份。实例参数修改不回写定义，不影响其他实例。
3. **共享发布副本**：按明确动作发布的完整资源包。后续修改工程定义不自动改变共享版；具体更新／标记／删除界面由RC3的D2／D3决定。

首批不引入实时组件联动。定义更新不自动改变既有画布实例；未来若增加替换／更新实例操作，需要单独合同。资源身份、原对象ID与Module ID不是同一种身份，不能互相代用。

## 3. 基础参数快照规则

| 数据 | 保存规则 |
| --- | --- |
| 对象type、名称、宽高、比例、斜切、角度、pivot、Alpha、混合方式 | 保留当前Scene存储的基础值，不调用播放头求值器采样 |
| 根对象位置与parentId | 从原父级脱离；定义以自身局部原点定位。创建实例的位置由放置操作决定，不复用旧父级坐标 |
| 图元与独立图样／附着拓展 | 保留局部几何、稳定part身份、外观、配方与精确版本／匹配快照；不自动拆成独立场景对象 |
| 对象effects及pipeline | 保留基础配置、启停、蒙版和处理阶段顺序；遇到未知实现明确报告，不用默认效果替代 |
| 基础循环动态 | 保留对象和图元anim及对象效果中的动态配置；不是把动画预先烘焙为一帧 |
| procedural.params | 保存此实例的完整基础参数；Manifest默认值仅用于实际缺省项，不覆盖已有值 |
| 文字 | 保留可编辑文本、排版、完成度／光标基础设置、rasterAssetId／glyphAssetId和布局信息；字体可用性单独报告 |
| timeline.tracks／visibility | 不保存、不按当前段合并、不把隐藏段的值写成基础值 |
| sceneVariants及场景级设置 | 不保存场景变体；保留对象基础值。实现依赖场景上下文的程序需报告可迁移边界 |
| 选择／下钻／solo／armed／历史／已获授信／运行缓存 | 不保存为素材内容，不跨工程继承 |

快照结果必须不受播放头位置影响。同一基础Scene在0.2s和2.8s入库，应得到相同的内容定义；缩略图也必须基于这个定义，而不是先截一张受时序影响的当前画面冒充基础预览。

根位置归一化不能简单递归把所有x/y减去一个数。图元坐标、静态蒙版的场景坐标、followMatrix、引用对象坐标和程序局部坐标不同：RC2必须用有类型的适配器平移／重建绑定。没有经过验证的坐标关系先明确拒绝，不通过偷偷保留父组、烘焙或丢弃蒙版掩盖差异。

## 4. 引用闭包与身份重映射

### 4.1 必须收集的来源

| 来源 | 当前实际字段／入口 | 捕获政策 |
| --- | --- | --- |
| 图片／多帧 | assetId、frames、fps、frameLoop | 携带完整字节与基础播放设置 |
| 非破坏处理 | sourceAssetId、recipe、alphaMask.locator | 携带原图恢复基底、处理配方与Alpha；不能只存当前抠图结果 |
| 文字快照 | rasterAssetId、glyphAssetId、textLayout | 两类图片都要入闭包；不能遗漏内置隐藏素材 |
| 图样 | parts[].recipe、definition/providerKey、geometrySnapshot、resourceBindings.pattern；extensions | 保留实际使用的精确实现／参数与匹配快照；目录是否展示不决定实现是否可用 |
| 对象蒙版 | effects.mask.type=element → targetId | 将来源作为内部依赖保存，不再指向原工程对象 |
| Alpha蒙版 | effects.mask.type=alpha → assetId（读入需识别已有imageId别名） | 素材闭包及坐标／跟随绑定均须适配 |
| 元素排布 | extensions.elements.sourceId | 捕获来源对象及其传递依赖 |
| 路径端点引用 | pathEndpoints.type=object → sourceId | 和排布共用对象闭包；多处引用同一来源只保存一份 |
| 程序实现 | moduleId／moduleVersion、manifest.assets、源码locator | 携带原实现与声明素材；不得执行源码以猜测依赖，也不得重写源码内字符串 |
| 字体 | fontId／fontFamily | 字体文件通用资源适配尚未完成；可保留现成字形外观，但不能因此承诺字体缺失时仍可原样改字 |

除已启用项外，保留下来的关闭配置如果仍持有有效引用，也应包含对应依赖，以便用户重新启用。无效或未知引用必须在预检中报告，不静默删字段。实施时需有明确引用字段适配，不对所有包含Id的字符串做统一替换。

### 4.2 根对象与内部来源

定义区分可见根节点和仅供引用的内部来源。放置后不能把蒙版／排布来源当作额外可见对象浮在画面上，也不能简单将它们设为hidden而导致引用渲染同样消失。RC2需明确其保存和Runtime角色适配，再进行像素验收。

首批来源为支持的普通／程序元素。引用组、粒子或需要保留外部父级语义时，预检说明超出首批范围；不会因为根不是组就绕过组依赖的限制。

### 4.3 三套映射，而非一个字符串替换表

- 对象ID：根、内部来源及targetId／sourceId等有类型的对象引用。
- 素材ID：位图、序列、原图恢复基底、Alpha与文字图集。
- 实现身份：Module及图样定义的ID／版本／内容绑定，按现有冲突规则校验。

例如对象叫`stamp`、位图素材也叫`stamp`时，排布sourceId需要映射到新对象，而image.assetId需要指向导入后的图片。这不是一个统一ID空间。part ID按所属对象管理，不将其误当全工程对象ID。

Module或其声明素材发生同名不同内容冲突，继续明确拒绝，不擅自改源码；普通素材及对象身份可在完整映射后原子复制。循环引用、缺失依赖、未知类型和超预算都在提交前失败，不自动带上整个Scene逃避分析。

## 5. 保存与实现策略：复用而非重写

RC2拟增加一个“元素预设”资源适配层，复用现有资源包、SHA-256、闭包、原子导入及项目包。实现中的kind／字段命名需在RC2设计小批中与校验器同步落地；本合同不声称现有包已经接受element。

持久Scene仍保留现有assets／modules／patternDefinitions等职责，不把对象实例塞入位图assets，不建立第二套Runtime。元素定义保存到独立的编辑器预设集合，创建后仍生成现有v4实体；集合字段需由RC2和项目包往返一起确定。

完整预设至少要表达：定义身份、一个可见根、支持的内部对象、基础参数、精确实现绑定和外部资源依赖。预设自身不保存原工程timeline或隐式文件路径，也不依赖全局共享库在线存在。未使用预设的项目保存与交付裁剪规则必须补测，不能仅给画布实例建路径。

这不同于现有R4“新建程序”：R4按Manifest默认值创建一个对象；新功能应从元素预设恢复实例已保存的参数、外观与依赖。R4烘焙仍是可选的像素结果，不作为元素入库的中间步骤。

## 6. 已执行的六组审计样例

输入由 `tests/fixtures/rc1-element-material-cases.mjs` 构造；它们是供RC2复用的测试输入，不是可由编辑器直接导入的新格式。没有新增外部图片、模型或网络依赖。

执行：`node tools/scripts/audit-element-material-rc1.mjs`（从外层工程目录）。脚本只在内存中调用现有资源API，校验输入未被改变、源码未执行；不写工程、不输出生成文件。

| 样例 | 当前API核对结果 | RC2需要新增的能力 |
| --- | --- | --- |
| 处理图片＋Alpha＋原图 | 现有asset包能携带并恢复original／prepared、recipe与Alpha描述 | 将这些依赖与对象基础Alpha／变换一同包装为元素 |
| 两帧序列＋基础bob | 位图资源保留两帧和2fps；bob属于对象，未被资源捕获 | 保留全局动态而排除时序 |
| 带括号图样的矢量 | 现有pattern预设保留配方参数与样式，不包含宿主元素 | 保留宿主、part、anim与精确图样绑定 |
| 当前雨量88、Manifest默认60、时段值240的程序元素 | 现有module包只有定义／默认声明，不携带当前实例参数或时序 | 保存88及其他基础参数，不取60或240 |
| 蒙版＋排布＋端点共用来源 | 图中需要host／matte／stamp，不需要unrelated；对象和位图同名合法 | 有类型的闭包、去重、映射与仅供引用角色 |
| 可编辑文字 | raster、glyphs与fontId是三种不同依赖 | 两张图片都携带；字体未适配时显式说明编辑限制 |

RC1时脚本曾核对`kind:'element'`被拒绝；该过期断言现已退役，脚本仅保留原资源适配边界审计。RC2-a以`tests/v4-element-presets-contract.mjs`及`tests/browser/v4-element-presets.mjs`正向验证捕获／导入／放置、工程往返和固定时间像素对照，已接入verify-v4。RC1审计本身不是功能成功测试，也未进行Tauri验收。

| 现有落点 | 可复用 | 不能直接当成元素素材实现的原因 |
| --- | --- | --- |

| v4-module-instances.js | Manifest参数归一化、局部尺寸、显式授信后的对象创建 | 当前创建默认实例，不是恢复用户保存的完整参数 |
| vnext-project-package.js／vnext-scene.js | 工程保存、重开、素材与模块携带 | 新预设集合的索引／恢复／未使用保存需要显式适配，不能假定unknown字段保留就已完成 |

## 8. RC2小批建议与停止条件

1. **RC2-a 最小独立元素**：普通／程序对象基础快照、排除时序、精确参数、定义与实例分离、两实例独立、原对象不变；无外部对象引用时先完成正向API及工程往返。
2. **RC2-b 依赖闭包**：位图预处理、序列、文字图片、图样、Module声明资产及冲突原子性；不增加新面板。
3. **RC2-c 外部对象来源**：仅支持的来源闭包、坐标转换、仅供引用角色、循环／超范围报告，固定时间实际像素对照。
4. 以上通过后再进入RC3的真实收入库／项目共享入口。未完成的小批必须显式标注能力限制，不以RC2-a完成宣称完整元素素材可用。

每批的四层清单：数据／Registry→UI命令（本阶段可先无新入口）→Runtime／Resolver／Host→测试。RC2默认不改变普通复制粘贴保留时序的既有行为，不新建通用插件系统，不启动自动恢复上次工程，不实现尚待讨论的图样面板。
