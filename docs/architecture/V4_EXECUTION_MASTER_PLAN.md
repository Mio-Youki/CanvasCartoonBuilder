## 目标

同一份 v4 工程应能产生三种边界清晰的结果：

```text
工程包（继续编辑） ──┬─> runtime.js（网站部署）
                     ├─> embed.html（复制/分享）
                     └─> PNG / GIF / Sprite 等像素交付
```

工程既支持普通声明式实体，也支持 Agent 生成的受控场景模块；模块不是 Legacy Runtime 兼容层。

## 已有素材库工作与本计划的关系

素材库计划 A–D 继续有效：普通素材/序列预览、精灵图临时切帧、预处理、文件夹批量导入都属于 P1 的输入能力。P1 不重写这些交互，只将“确认入库”的内存素材写为正式工程包。

明确区分两件事：

- **P1 显式打开**：用户选择一个项目包并恢复它；这是保存协议的必要验收，不依赖 IndexedDB。
- **P6 自动重开**：浏览器记住上次项目/目录授权；这是便利功能，当前暂停。

## 不得漂移的约束

1. 保存不得自动删除未使用素材；清理只能是显式、可预览的命令。
2. Runtime 不访问磁盘、网络、IndexedDB 或编辑器 DOM；Host/Storage 负责解析资产。
3. `scene.runtime.js`、`scene.embed.html`、编辑器预览和离线导出必须使用同一 v4 Runtime 语义。
4. Scene Module 是正式创作出口；不能为了 JSON 纯度强迫 Agent 将复杂画面拆成低层图元。
5. Builtin 只收录跨项目通用能力；具体场景美术优先是外部模块、素材或普通实体。
6. 不在 v4 编辑器内执行 Legacy `home-scene.js`、`program.code` 或旧专用绘制函数。
7. “不能自动降级为声明式”不等于“不能迁移”；作品专用绘制优先适配为项目 Scene Module，只有跨项目稳定复用的能力才晋升 Builtin。
8. `home-scene` 第一轮是一个完整项目 Module，不拆成十二个永久构件；此策略只用于保真基线，不要求未来 Agent 场景一律模块化。

## P5 的质量门禁

每个 Agent 实验至少记录：视觉目标、可编辑参数覆盖、背景依赖程度、固定时间确定性、预览帧耗时、发布体积。固定案例为：纯文本雪花球、单图氛围动态化、粗糙波普拼贴。

具体的控制组、变量、载体选择报告与成功门槛见 [Agent 场景实验协议](V4_AGENT_SCENE_EXPERIMENT_PROTOCOL.md)。
