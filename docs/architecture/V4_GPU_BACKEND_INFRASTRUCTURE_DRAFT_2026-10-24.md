### 接入前发现的宿主缺口

1. `editor/vnext-workspace.js` 的 `invalidatePlayer()` 直接清引用，没有释放旧 Player。GPU 接线前必须补齐显式释放，覆盖 mutation、replace、尺寸变化和关闭。
2. `editor/classic-v4-view-controller.js` 的 `shown !== value` 分支创建临时 Player，没有明确释放。需要在 finally 中释放，并避免错误时遗留上下文。
3. Workspace 已有 revision 和异步创建期间的版本检查，但素材解析缓存写回还需验证“旧工程解析完成后不覆盖新工程”的隔离。不能直接把文档 revision 当作完整来源版本承诺。
4. 当前预览调度已有 rendering/rerender 串行保护；新增后端不能绕开它。还需核对直接 render 调用、临时预览与切换项目期间的提交隔离。
5. GPU 计划已经消费 frame 求值结果；部分动态准备仍在具体内核中。需要盘点与 CPU 共用的准备函数，禁止新增另一套动态公式。染色已经复用 `decorate.animated`，不重写。

上述为静态审查发现；本批没有运行浏览器或重新测量性能，不能据此宣称实际资源泄漏幅度或修复通过。

## 2. 能力合同草案

### 2.1 唯一声明入口

现有 Registry 继续是效果语义、ID、参数和时序的唯一目录。建议增加 `backendCapabilities` 查询接口，按已有 effect/controller ID 与 implementation revision 关联后端声明；不要复制名称、参数、默认值和控件定义。

实现侧提供不依赖 DOM 的能力记录与纯条件检查，Registry 引用这些记录。运行时构建须能加载同一份能力数据，而不是反向依赖编辑器 DOM 脚本。具体新模块路径与构建顺序在下一批确认；不把完整 Registry 打包到 Player。

受信图样生成器的宿主注册记录使用同一种能力描述，但以生成器稳定 ID 为目标，不加入第二个效果菜单。项目携带的 manifest 不能自称拥有可信 GPU 实现；能力来自宿主实际注册的实现。未声明时标为未核验，不猜测 GPU 支持，也不影响已有 Canvas 实现的合法使用。

### 2.2 描述结构

以下是宿主内部结构示意，不是作品 JSON 新字段，也不是已经实现的 API：

```js
{
  target: { kind: 'effect', id: 'threshold', implementationRevision: '…' },
  semanticScopes: ['object', 'scene'],
  implementations: [{
    backend: 'webgl2-scene',
    status: 'experimental',
    scopes: ['scene'],
    input: 'evaluated-rgba-capsule',
    conditions: ['…已注册的条件 ID…'],
    semantics: {
      alpha: 'premultiplied-rgba8',
      bounds: 'scene-extent',
      mask: 'cpu-resolved-upload-per-effect',
      blend: '…能力约束…',
      order: 'existing-scene-overlay-then-sample'
    },
    invalidation: ['source', 'parameters', 'time', 'seed', 'size', 'context'],
    costModel: '…可执行估算器 ID…',
    evidence: ['…夹具及结果引用…']
  }]
}
```

每条声明还必须包含：

- 支持条件、不支持条件、稳定回退码；条件检查读取已求值参数、输入表面及设备能力，不读 Inspector 私有状态。
- 内容生成与后处理分开声明。`canvas2d` 图样生成可作为场景 WebGL2 输入，不等于该生成器有 Shader。
- Alpha 表示、工作边界／padding／裁切、坐标空间、蒙版来源与反相、支持混合方式、顺序约束。
- 静态／动态的时间键、seed、依赖资源版本；No／Step／Linear 仍来自统一参数声明，后端不重新定义可动画参数。
- 工作像素、遍数、纹理上传次数／字节、显式回读、显式存储字节、CPU 准备与数值表构建／更新。Canvas→GL 上传与 GL→Canvas 输出单独计数；没有显式 readPixels 不等于没有传输／同步成本。
- 画质验收配置、测试证据、适用设备及未测项。预算估算与实测分开；未测量为 null／unknown，不填 0。

### 2.3 当前应登记的能力，不扩大承诺

| 能力 | 场景共享 GPU 的已实现条件 | 明确边界 |
|---|---|---|
| 采样格 | 最近邻，Alpha keep | remove／boost 整链 CPU |
| 染色 | 字符串颜色；normal／screen／lighter | lighter 不是 lighten；其他混合、非字符串 Paint 整链 CPU |
| 杂色 | 单／彩色、颗粒尺寸、seed、刷新及 Step | 数值准备表仍有 CPU 成本，不是 CPU 缓存噪声图片 |
| 阈值 | 既有颜色和阈值呼吸／Step | 保留 JS 临界亮度与字节舍入，不用近似更改选色 |
| 不均采样 | 波／径向／受支持整数尺度噪声场，既有动态 | 非整数噪声尺度、启用边缘保护等不支持条件整体回退 |
| 边缘色散 | 既有边缘规则、色序、Step | 超可靠坐标范围等整体回退，不缩小 UI 输入范围 |
| 其他效果 | 共享执行器尚未覆盖 | CRT／ASCII 独立路径不能算本链覆盖；网点实验不等于正式接入 |
| 路径图样 | 当前受信 Canvas 绘制实现 | 载体、覆盖顺序、裁切与参数时序不变；GPU 生成未实现 |

未来自定义效果只有注册实际实现、条件、预算和证据后才能提升状态。仅声明 `gpu:true` 或安装 manifest 不授予后端能力。

### 2.4 计划、实际结果与回退

```text
统一参数求值 → 语义操作链 → 无分配条件预检
                            ↓
                    宿主请求 CPU / 实验 GPU
                            ↓
               设备初始化／整链执行／当帧验证
                            ↓
               实际后端 + 成本计数 + 回退诊断
```

预检时设备尚未创建可标为 unknown，不伪造 available。通过纯语义预检后才惰性初始化。保留现有 `sceneGpu.plan` 的调用兼容性，逐步补充结构化结果，不先推翻执行器。

建议诊断条目包含 `code / scope / ownerId / effectId / parameter / observed / required / retryable`；保留现有 reason 文本以兼容测试。需要区分：主动 CPU、无效果、不支持语义、设备不可用、上下文丢失、资源／绘制失败。

实际统计分开记录对象内容生成、对象处理、当前／上一场景处理与最终转场。不能以一个 GPU 标签掩盖对象仍在 CPU 上运行。一个阶段整体 CPU 回退，不在卡片之间随意往返。场景和对象是不同阶段，不承诺整个应用只有一种后端。

不支持参数只对当前计划回退；设备故障按现有执行器策略记忆，清缓存后允许重试。失败必须当帧完整 CPU 重画，不能用旧纹理补位。

## 3. 缓存、资源和宿主接线

### 3.1 生命周期

- Player／会话是资源所有者；共享数字表不能持有项目或素材引用；借用执行器不得释放拥有者资源。
- 替换项目、撤销／重做导致 Player 替换、改尺寸、关闭、临时 Player 完成／失败均释放旧资源。
- 异步素材解析带会话代号和文档版本；失效结果不回写新会话，不触发旧画面提交。
- 资源统计区分 live／累计分配／释放／峰值；重复切换须观察 live 不持续增长，累计次数增加不是泄漏证据。
- 上下文丢失、GPU 绘制错误和清缓存后的重建分别验收。

### 3.2 缓存失效

第一版编辑器接线**不传 sceneSourceVersion**，保持每次来源刷新，先验证正确性与释放。仅在确认全部来源修改均推进版本之后启用输出复用。

完整版本至少覆盖对象／组／图元、附着图样及顺序、背景、素材解码完成与 Alpha 派生、字体、Module 参数、引用蒙版、尺寸、预算变化、撤销／重做。时间、已求值参数、seed、上下文代次与工作尺寸另入键。缺任何环节就保守重画；暂停不能成为缓存有效性的充分条件。

GPU 输出缓存命中也不代表跳过 Canvas 对象绘制。不要把这一层描述成完整编辑器帧缓存。

### 3.3 显式实验入口

沿用舞台预览区域，新增最小宿主策略选择：CPU 基准／实验 GPU。默认 CPU，策略仅属于编辑器会话，不保存到作品，不联动 Inspector 参数。

显示请求与实际结果，例如“请求 GPU；场景 CPU：纹理叠加尚不支持”。可展开诊断查看对象仍为 Canvas、两侧场景及转场后端、回退码和资源计数。具体控件样式交由 UI 会话；本会话只提供状态与事件接口，不重排 Inspector。

建议独立控制器提供 `setPolicy / previewOptions / observeFrame / reset / dispose`。后端切换使调度器失效；项目替换清除诊断历史，策略是否跨项目保留只属宿主偏好，不改变作品。

首批只接已有 `sceneBackend` 与可选 `sceneProfile`。GPU 最终转场、frame-end 验证、fixed-roles 保持既有显式实验选项，不随 GPU 选择隐式全开。

### 3.4 计时口径

| 指标 | 测量边界 |
|---|---|
| 编辑器 render | 现有视图 render 完整异步区间，含准备和选择框；避免与其它分项相加 |
| 素材／Player 准备 | await 解析与创建，首次和预热分别记录 |
| Runtime 调用 | Player 准备完成后同步 renderTo 调用区间；不是 GPU 执行时间 |
| 播放调度 | 请求目标 FPS、实际回调到达间隔、RAF 时间戳分别记录 |
| GPU 设备时间 | 可选异步 timer query，有效样本及 disjoint 独立记录；不支持则 unavailable |

不以 gl.finish 强制同步制作日常 HUD。计时查询需有界回收，不嵌套已有测试 query。设备时间不包括 Canvas 和 CPU 准备，也不能与完整调用相加得到总帧耗时。

## 4. 对象管线：复用与缺口，暂不实施大改

当前胶囊已有明确接线点：content → formation → 用户排序的 mask/decorate/sample → 最后对象及父级 Alpha、混合、场景定位。保留这条链、实际 localBounds、padding、世界坐标和重复滚动语义。

可复用：预乘字节协议、采样／阈值／杂色等 Shader 内核、数值表、纹理 ping-pong、错误回退与诊断结构。不能直接复用的假设：全场景尺寸、scene effect resolver、范围蒙版坐标、场景固定顺序和双侧转场资源角色。

**建议首个验证对象为采样格＋阈值分色**：当前 CPU 使用 withPixels，已有严格 GPU 临界值内核，能同时检查透明图片、文字、多图元胶囊；先做原型及端到端成本，不承诺收益。不均采样收益潜力更大，但边缘保护和对象坐标尚未覆盖，不适合首个低风险试点。

试点只允许整个受支持 sample 阶段进入 GPU，再输出给原对象合成；遇到同阶段其它不支持效果，整个 sample 阶段保持 CPU。不把对象输入伪装成 scene JSON。蒙版／加样在用户指定的位置照常执行，最终 Alpha／混合只应用一次。

一页不创建每对象一个 GPU 上下文。后续需要 Player 所有的共享设备服务及按尺寸／用途租用表面；场景执行器当前按尺寸重建的资源不能直接作为多对象池。该调整涉及执行器资源所有权，必须另批审阅后实施。

必须计入对象 Canvas 输入、上传、GPU 执行、返回 Canvas 与原场景合成的完整成本。混合 Canvas 合成器下仍存在传输，不能只报 Shader 时间。若代表对象负载没有端到端收益，保留 CPU，不扩大覆盖。

## 6. 验收矩阵

每批结果记录提交／工作树标识、设备与驱动、浏览器版本、尺寸、预览预算、初始化耗时、预热数、样本数、P50/P95/最大值、有效设备计时数、上传／回读／遍数／显式内存。

1. CPU/GPU：透明／不透明、文字／矢量／图片／附着图样来源、临界值、独立反相蒙版、Step／已有合法 Linear、seek 往返。断言实际求值变化，防止两边都未生效而通过。
2. 正式编辑器：添加／改参、暂停连续修改、撤销／重做、素材异步完成、切换项目、改尺寸、切后端；等待操作完成并核对实际像素，不只断言返回状态。
3. 无效果、单效果、完整支持组合、不支持组合；静态与持续动态分开测，连续染色变化单列 CPU 准备预算。
4. 无 WebGL、上下文丢失、分配／绘制／最终转场故障：当帧完整 CPU 结果，不残留旧输出；原因可见。
5. 重复项目切换、清缓存与 dispose 后，live 资源归零／回到预期基线，异步旧结果无污染。真实浏览器还需休眠／恢复测试。
6. 保留现有严格透明及临界边界门禁；不为过测试放宽图像阈值。画面近似若有必要，另行征求用户批准。

历史证据供基线参考，不是本轮新测：Intel UHD620／Edge／ANGLE D3D11，8 预热＋64 样本，1080p 五卡无范围完整调用 P95 CPU 168.0ms／GPU 18.7ms；五卡各有范围 198.0／43.5ms；双侧范围＋GPU fade 403.8／81.6ms。显式纹理约41.56／57.38MiB，不含 Canvas／驱动。这些是 Player 结果，不是当前编辑器或 Tauri 成绩，不能承诺稳定30fps。

本轮后续不重测已经收束的来源传输微基准作为主要成果；优先完成能力声明、真实宿主与回退链。
