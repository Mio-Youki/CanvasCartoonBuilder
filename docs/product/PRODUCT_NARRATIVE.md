# Patcharium / 拼好景：产品叙事

> 当前对外工作名称：**Patcharium / 拼好景**。技术仓库名暂保留 CanvasCartoonBuilder / Pixel Scene Builder，待三案例与 Agent 协作验证完成后再决定正式迁移。

## 一句话

把一张图、一些图层和一点时间，拼成会一直运行的小景。

## 目标与背景

Patcharium / 拼好景是一个轻量 Canvas 场景工作台。它不试图取代视频剪辑器，也不强迫创作者把高细节图像拆成无数代码图元；它让底图、语义图片、图元、粒子与效果共同组成一个可持续运行、可编辑、可迁移的微缩世界。

产品意象来自雪花球、鱼缸布景与拼贴切口：容器中有前中后景、光、颗粒和小变化；拼贴的边缘、描边和修补痕迹是创作过程的一部分。像素、CRT 与故障是可选材料，而不是唯一的身份。

## 承诺与边界

- 核心交付物是可自包含运行的 JavaScript 场景；GIF、PNG、精灵图是派生出口。
- 高细节可由图片承载；只有有明确编辑收益的区域才结构化。
- Canvas 2D Runtime 保证同一 Scene 在编辑预览、固定时间测试与帧导出中的一致语义；它不承诺任意 HTML、视频、WebGL 或 shader 都能导入运行。
- “轻量”指 Runtime 与场景结构可移植，不等于每件作品都小于固定文件体积。作品预算由画布像素、每帧层数/粒子/FX 和嵌入素材共同决定。

## 人与 Agent 的分工

Agent 的职责是视觉拆解、Scene 初稿、结构化局部修改和验证建议；人的职责是决定素材化与结构化的边界、修正构图和节奏，并为作品作出审美判断。Agent 不被承诺为一次性完美重绘工具。

优先走外部 Agent 工作流：公开规范、样例和验证入口，让任意具备视觉能力的 Agent 生成可导入初稿；内置对话只会复用同一份 Agent Tool Protocol，不能另建不透明的编辑语义。

## 发布验证

首批验证三类作品：

1. 微缩景观/雪花球循环：建立产品记忆点；
2. 静图转持续氛围场景：验证通用性；
3. 粗糙波普拼贴循环：验证快速传播与表情包方向。

每例的最低通过线为：编辑器预览 → 保存自包含 JS → 独立测试页 → PNG/GIF 导出，结果一致；同时记录文件体积、导出耗时、可编辑对象与人工修正过程。Agent 协作成功还需满足：初稿可导入、用户无需改代码即可完成关键修正、修改后可通过同一验证链。

## 发布节奏

先“作品展示优先”，再邀请熟悉 GitHub、本地文件和 AI 工具的创作者公开测试。首批内容让人记住“一张图，做成会一直运行的小场景”；Agent 作为幕后协作过程出现，不抢先成为未经验证的主承诺。
