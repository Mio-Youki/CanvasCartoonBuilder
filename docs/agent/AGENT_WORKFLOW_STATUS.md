# Agent 场景生成：试验总结与待决问题

> 本文记录截至当前版本的试验过程和共识。它不是格式合同；字段以 `../../SCENE_SPEC.md` 为准，
> 生成步骤以 `AGENT_GENERATE_SPEC.md` 为准。

## 1. 初始目标

让具有视觉能力的 Agent 根据文字和参考图，生成可被 `img2asset.html` 打开、编辑、保存并再次打开的
`GENERIC_SCENE`。理想闭环是：生成场景 → 用户在工具内调整 → Agent 依据元素名/参考图局部迭代 →
保存为可运行 js。

目标并非单纯“生成一张好看的图片”，而是尽可能保留图层、图元、素材、动画和显示时段的编辑价值。

## 2. 初次试验：纯 parts 重绘河谷

以河谷松林参考图为例，初次方案使用纯 `parts` 重建白天与夜晚，并加入河流波光、树叶摆动、转场和萤火。

### 得到的成果

- 验证了 Agent 能产出合法 `GENERIC_SCENE`：两幕 `show`、scene 边界、内建 dissolve、partsBand、
  part 动画和 particle 均可用。
- 形成了 `examples/river-valley-two-acts.js` 与纯图元的静态锁定对照样例
  `examples/river-valley-static-lock.js`。
- 暴露了格式层与视觉层的差异：文件可解析、可编辑并不等于画面具有参考图的层次和笔触。

### 失败原因

- 参考图的远近树林、山体、河岸和水面依赖高密度像素簇、复杂遮挡与非规则笔触；用少量 `poly`、
  `rect` 和线条会自然退化为“图标化的三角松树”。
- 增加同类图元数量提高的是代码与编辑负担，不会线性提高还原度。
- 初版同时处理静态重建、结构规范化和动效设计，动效掩盖了静态构图未锁定的问题。
- 默认 16:9 画布与参考图 3:2 的比例差异进一步损失构图。

## 3. 调整过程

1. **静态优先**：将生成流程改为“参考拆解 → 静态基底 → 同尺寸视觉锁定 → 结构整理 → 动画覆盖”。
   静态阶段不加入动画、粒子、FX 或转场。
2. **比例优先**：河谷样例改用 360×240（3:2）作为静态对照尺寸。
3. **视觉审稿分离**：试验了子 Agent 只做视觉审稿，不修改文件；主 Agent 负责实现和格式自检。
   审稿结论明确指出：树林应被当作连续纹理/树群，而非多个独立松树图标。
4. **混合底图试验**：白天与夜晚分别使用同构图底图，程序层只叠加安全水域内的波光、星点和少量萤火。
   对应样例为 `examples/river-valley-hybrid-two-acts.js`。

## 4. 已达成共识

### 数据与保存

- 正式 js 应携带处理后的素材快照（data URL），确保作品可独立运行。
- 桌面应用后再增加 `assetRef`、原图路径和处理配方，使素材库能重新定位原图并再处理；快照与引用并存，
  前者负责可携带，后者负责回编辑。

### 可编辑性预算

- 不把图片底图当作默认答案，否则工具会退化为图片叠特效器。
- 高密度、静态、不会单独移动/换色/交互的区域可由底图承接。
- 需要移动、替换、变形、单独改色、响应交互或产生时序变化的对象，必须拆为图片层、sprite、图元或粒子。
- Agent 应先输出“元素/载体/可编辑项/保真理由”表；用户可决定哪些区域优先保真，哪些优先可编辑。

### 多参考图与文本

- 不能先把所有图机械合成为一张，再让 Agent 临摹。
- 文本定义叙事、镜头和动效重点；每张参考图应先标注为构图、风格色板、材质、对象细节或动画参考。
- 先由视觉规划得到一张场景蓝图，再由实现 Agent 写合规 Scene；只有确实不可拆的静态区域才生成/合成底图。

### 多 Agent 职责

```text
视觉规划 / 审稿 Agent：参考拆解、层次和偏差报告，不修改场景
实现 Agent：在当前 Scene 合同内生成或迭代场景
改写 Agent：仅处理旧 JS / 外部 JS 的格式修复与参数化迁移
主 Agent：决定迭代、运行格式与保存往返校验、维护文档和兼容性
```

改写 Agent 不能弥补生成阶段遗漏的视觉层次，因此不应承担“提高还原度”的职责。

## 5. 当前能力边界

- 当前 Runtime 支持 parts、图片、背景、sprite、scroll、动画原语、图片采样闪变、粒子、FX、转场、多场景显示窗口，以及 rect / ellipse / poly / Alpha / 明度 / 元素实时蒙版。元素蒙版可引用已有元素或组的当前 Alpha，并继承其时序与动画；它不替代复杂静态底图的素材化判断。对象、局部 FX 与全局画面的采样/色板作用域已分离，Agent 必须明确效果落在哪一层。
- 工具支持图层与 parts 的编辑、排序、素材处理、背景布局和保存；`GENERIC_SCENE` 可往返编辑。
- 背景图片仍可作为一个可控制显示时间、透明度和多帧播放的素材层，但其内部像素并不会自动变成可编辑图元。
- 元素与局部 FX 已支持几何蒙版及引用透明 PNG 的 Alpha 蒙版；这可把“树冠 / 树干 / 水面”等高细节静态素材定义为语义区域，并由 FX 安全局部改色。当前仍没有羽化、灰度亮度蒙版、嵌套裁剪组与自动分割生成蒙版。
- 当前没有参考图叠加/差异预览，也没有固定时间的渲染回归，视觉迭代仍依赖人工审稿。

## 6. 当前产品结论与验证方向

- 产品不以“AI 一次重绘完美参考图”为承诺，而是以可携带、持续运行的混合小景为核心产物。
- 当前优先验证外部 Agent 协作：Agent 依据公开协议生成/修补场景，人使用编辑器完成局部判断与修正；内置 Agent 仅在该协议稳定后再评估。
- 公开验证固定为三类案例：微缩景观/雪花球、静图转持续氛围场景、粗糙波普拼贴循环。每例必须走完预览、保存、自包含测试页与帧导出的一致性检查。
- 质量判断分为视觉层（构图、层次、色板、素材判断）与结构层（可编辑项、稳定 id、保存往返、Runtime/导出）；任一层失败都不能称为成功的 Agent 场景生成。

## 7. 待解决问题

### 近期：Agent 工作流

1. 把元素表正式做成生成 Agent 的必交付物，并让编辑器可显示/定位这些元素名。
2. 增加参考图叠加、透明度对照和局部放大，支持“只修改某个命名层”的迭代。
3. 建立可复用的多参考图输入模板：参考角色、优先级、冲突处理和可编辑性预算。
4. 为视觉审稿增加固定时间的渲染结果输入，避免只分析文字或代码。
5. 定义质量门槛：构图/比例/层级/色板/可编辑项/性能分别验收，而不是只检查 Scene 能否解析。

### 中期：编辑能力

1. 蒙版进阶：现有 Alpha / 几何蒙版增加羽化、灰度亮度、局部包围盒缓存与嵌套裁剪组；限制粒子、sprite、波光与雾的可见区域。
2. 图片分层与可编辑元素的组合：使静态底图和独立对象能有清晰的覆盖、替换与显示时间规则。
3. 桌面项目层：实现素材原图、处理配方、`assets/`、跨场景素材库及 Scene 的稳定引用。
4. Runtime Adapter：将预览、固定时间帧、导出和未来关键帧求值统一在同一离线可渲染内核中。

## 8. 当前决策

Runtime Adapter 的固定时间渲染、PNG 序列与 GIF 导出基础已具备。现在恢复 Agent 工作流，但不盲目扩张
schema：先建立可复现渲染、视觉对照、结构 Patch 与三案例验收，再决定是否引入桌面项目层、内置对话或更复杂的
关键帧/素材能力。
