# 循环运动合同 v1

更新：2026-10-25。实现唯一来源：`runtime-src/vnext/29-motion.js`，公开为`ToSampoolRuntimeVNext.modules.motion`。本合同约束动态时间计算，不取代效果Registry、图样生成器或项目Module的参数／安全协议。

## 三类原语

| 原语 | API／值 | 用途 |
| --- | --- | --- |
| 往返 | `oscillate(spec,time,options)`，-1到1 | 位移、角度摆动、透明度起伏、阈值偏差 |
| 循环推进 | `progress`返回周期内0到1；`advance`保留累计圈数 | 旋转、纹理移动、放射图样 |
| 随机刷新 | `refresh`返回确定帧号，不直接生成随机像素 | 颗粒、杂色、随机保持 |

`clock`提供周期、周期序号、相位、帧号与逐帧状态；`ease`和`curve`为底层节奏函数。不要直接组合`curve(motionTime(...))`实现逐帧往返：中心起相的正弦／三角波在两帧时会被取成同一个值。

### 参数及默认规则

- `period`：周期时间，秒，大于0。速度驱动的旋转／重复滚动应在适配层推导周期，不同时开放两个互相矛盾的可写速度／周期。
- `curve`：`linear/smooth/ease-in/ease-out`，显示“均匀／柔和／加速／减速”。往返默认柔和，单向推进默认均匀。旧step节奏仍可读取，不作为新效果的通用节奏选项。
- `stepped`：逐帧开关。关闭时连续求值，打开后渐进显示整数`periodFrames`，最小1。新基础动态／图样默认8；既有效果可以保留已登记的默认12等，不强制全产品同值。
- 既有效果的`steps`是`periodFrames`的适配别名，不要求改写旧协议。新构件优先使用`periodFrames`；读取既有Registry则使用它声明的`steps`。两者不要同时序列化；若外部输入同时出现，`periodFrames`优先。
- `options`供既有适配器明确默认值，例如阈值`{stepped:true,frames:12}`；显式`spec.stepped:false`优先于适配默认。不依据某字段“恰好存在”猜测是否逐帧。
- 往返连续模式沿用中心起相；逐帧模式统一从负端起相。2帧为`-1,+1`，4帧为`-1,0,+1,0`（均匀／柔和）。1帧为固定状态。奇数帧仍等时间取样，不承诺必定取到正端。
- 循环推进从0起相；2帧为0和半圈，而不是两个等价的整圈位置。绘制旋转图样使用`progress`防止累计角度增长；需要累计位移时使用`advance`。
- 随机刷新默认重复周期内帧号；`options.loop:false`才返回不回卷的累计tick。效果负责以固定seed、稳定身份和帧号生成随机结果；禁止使用`Math.random`或真实时钟补帧。

### 时间轴和闭合

时间来自宿主传入的场景时间，不创建自己的计时器／requestAnimationFrame，不把实际显示帧率当成运动配置。逐帧只量化运动，不提高编辑器或导出的fps。

动态开关和配置默认Step；运动本身连续不代表配置必须Linear。时序换参沿用场景时间，不自动从头播放；改周期可能跳到另一相位，不承诺速度积分或自动平滑衔接。需要重播／局部时间的效果须另行声明，不能悄悄减去轨段起点。

每个运动周期闭合不等于任意项目时长都无缝：项目循环时间须容纳整数个该运动周期，随机序列也须使用循环帧号。粒子寿命、非重复滚动和一次性过程不强行伪装成周期。

## Agent生成要求

提案及四层落点清单中声明：原语、作用参数与单位、基础值／幅度／边界、时间来源、周期／速度依据、逐帧规则、时序能力、随机种子和闭合条件。使用严格生成器schema时，这些说明放在提案／交付文档，不向Runtime声明硬塞未支持字段。

实现只负责映射原语输出，例如阈值=`基础阈值+幅度*往返值`，透明度起伏=`基础透明度*(1-幅度*(往返值+1)/2)`。效果可保留自己的单位和视觉参数，不为噪声硬加缓动、不把有向旋转改成往返。只有确有空间／物理需求时才能声明`effect-specific`，并写明不能复用的原因。

Registry和Manifest必须包含默认值、选项及显示名、渐进条件、No／Step／Linear能力。动态字段加入后同步Inspector和测试；不能只做可交互预览而遗漏正式Runtime或导出镜像。

### 最低验收

1. 固定时间重复结果一致；不修改传入配置。
2. 逐帧1／2／3帧、全部标准节奏、帧间保持与更新；两帧往返不得静止。
3. 周期首尾、负时间、正／反方向，以及非整周期项目的明确边界。
4. 参数Step、停用、撤销／重开，换参不隐式重播。
5. 正式Runtime真实像素、导出内联镜像一致；CPU／GPU有重复时间公式时必须同步验证，不通过CPU回退冒充GPU通过。
6. 不新增像素遍历或无界缓存；时间原语每对象／效果常数成本。需要像素计算的是效果自身，须另报预算和后端支持。

## 当前迁入与边界

已迁入：六种基础动态（对象与图元）、阈值呼吸CPU及GPU阈值边界、染色淡入淡出／闪烁、网点震荡、双色放射旋转、颗粒刷新。染色／阈值／网点的节奏与逐帧参数沿Registry接入；双色放射沿唯一生成器定义接入正式Inspector与审阅页。

双色放射新增参数发布为`proposal.dual-ray@2 / dual-ray-v2`，示例资源包和候选直接引用新版定义。保留严格的v1受控登记以读取已有项目／资源；不静默扩写旧声明，不自动覆盖用户共享库。目录每个稳定ID只展示最高版本，已附着旧定义仍按自身版本读取。新增节奏／逐帧控件需显式取用新版资源；旧记录不会凭空出现新参数。

未宣称全量迁入：其他图案运动、不均采样流动／潮汐、CRT、偏移采样等仍可能使用专用时间逻辑。它们在Agent manifest标为`effect-specific`，后续按算法语义逐项验收，不只更名或强塞通用参数。

验收：`v4-motion-primitives-contract`、浏览器`v4-motion-primitives`、基础动态／程序构件、纹理动态全模式、双色放射、GPU阈值Player定向回归。像素读回夹具预先设置`willReadFrequently`，避免连续getImageData导致浏览器切换Canvas栅格化后端而产生假差异；不放宽产品像素断言。未做全量verify-v4或Tauri验收。
