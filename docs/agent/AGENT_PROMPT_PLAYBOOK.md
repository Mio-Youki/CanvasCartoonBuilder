# Agent 提示词手册：三类 Patcharium 场景

> 本手册服务于外部视觉 Agent。字段合同见 [SCENE_SPEC.md](../../SCENE_SPEC.md)，协作动作见 [AGENT_TOOL_PROTOCOL.md](AGENT_TOOL_PROTOCOL.md)。它不要求 Agent 一次完成所有高级能力。

## 0. 通用提示词骨架

借鉴程序化视频工具的有效做法：不要只写风格形容词；一次任务应明确**输出介质、画布/循环、视觉构图、运动节奏、素材边界、验收方式**。HyperFrames 的提示词指南同样强调先说明时长、比例、风格和关键元素，并在预览后局部迭代，而不是每次从头重写。[参考](https://github.com/heygen-com/hyperframes/blob/main/docs/prompting/overview.mdx)

所有场景请求都可使用以下结构：

```text
你是 Patcharium 场景规划与生成 Agent。先输出“视觉规划”，确认后才输出 Scene。

【交付】输出合法 const GENERIC_SCENE = { ... }；不得 import、函数、eval、外部 URL 或自定义 Runtime 绘制代码。
【画布与循环】{宽}×{高}；循环 {秒}；场景段 {名称/数量}。
【视觉目标】{主体、镜头、前中后景、色板、材质、负空间}。
【运动目标】只列出 2–5 个有叙事意义的持续变化；其余静止。
【可编辑性预算】逐层选择：parts / 图片 / sprite / particle / FX；说明理由。
【素材】{资产清单或“无外部素材”}。不得编造 data URL 或不存在图片。
【限制】保持稳定 id；先静态后动态；不使用未在 Scene Spec 声明的字段。
【验收时刻】在 t={...} 截帧检查，并输出近似/不可保真说明。
```

第一轮只要求 Agent 输出元素表：`id / 名称 / 载体 / z / 可编辑项 / 运动 / 保真理由`。收到确认后，才进入 Scene 文件生成；文件通过 `validate-scene.mjs` 后，才进入视觉审稿与最小 Patch。

## 1. 雪花球：纯自然语言 → 微缩循环场景

### 能力边界

此案例适合验证**文本到结构化 Scene**，不适合验证高保真插画能力。无外部图片时，Agent 应创作图元化、低细节、明确风格的微缩景观；若目标要求复杂角色、手绘树群或高密度纹理，应先生成/提供一张底图，再转入案例 2。

### 规划提示词

```text
为 Patcharium 设计一个无外部素材的雪花球小景，先不要写 JS。

画布 360×240，循环 18 秒。玻璃球中是一间偏左的小木屋、积雪松树、远山和暖黄窗灯；底座为粗糙深蓝纸板。整体是安静、手作、像素拼贴感，不要写实。

请输出：
1. 前/中/后景与负空间；
2. 不超过 12 个可编辑语义对象，每项标记 parts、particle 或 FX；
3. 只保留四种运动：雪粒缓慢下落、窗灯轻闪、远景雾横移、偶发摇晃后的雪粒加密；
4. 哪些区域必须保持静态；
5. 不使用图片时的保真限制。
```

### 生成提示词

```text
基于已确认的元素表，生成合法 GENERIC_SCENE。

要求：360×240、18 秒循环、单场景；所有顶层对象均有稳定 id；用 parts 表达玻璃球、底座、木屋、树与远山；雪使用粒子；窗灯用 blink；雾只在球体内部的安全矩形蒙版内移动。不得添加未讨论的对象，不得添加全局 CRT/故障效果，不得用图片 data URL。

先确保 t=0 的静态构图成立，再加入指定的四种运动。最后给出元素表、t=0/6/12 秒的审稿重点与可编辑性说明。
```

## 2. 静图转氛围场景：单图参考 → 选择性动态复现

### 能力边界

Agent 不能可靠地从单图自动得到像素级分割或真实遮罩。它应把复杂静态区域保留为底图，把明确且安全的局部区域转为动画；水面、云、灯、烟、雨雪通常适合，复杂树冠、人物轮廓和不规则岸线默认不适合直接用大范围特效模拟。

### 规划提示词

```text
分析随附单张图片，将其转换为 Patcharium 的持续氛围场景。先只做规划，不输出 JS。

用户目标：画面从傍晚缓慢进入夜晚，河面有微弱波光，远处有偶发灯火，前景有一层低雾；循环 36 秒，不改变原图构图。

逐项输出：
1. 原图比例与建议画布尺寸；
2. 必须保留为底图的高细节区域；
3. 可安全做成独立语义图层或局部 FX 的区域及其近似包围盒；
4. 白天/夜晚是否需要两张同构图底图；
5. 运动预算（最多四项）、每项的强度与循环节奏；
6. 风险：哪些效果会破坏原画，因而不做。

不要声称已自动抠出树、人物或河岸。若缺少夜景素材，请明确要求用户提供第二张同构图或接受全局调色近似。
```

### 生成/修正提示词

```text
用户已将底图作为 imageId="valley-day" 导入场景，并提供同构夜景 imageId="valley-night"。
请只输出一个最小 Scene Patch：

- 保持两张底图构图、尺寸与层级；
- 用 show 和 dissolve 在第 18 秒切至夜景；
- 在已确认的河面矩形/多边形范围内增加波光粒子或局部效果；
- 在前景低雾范围内增加弱像素雾；
- 不触碰树冠、山体和河岸本体；
- 给出 t=0、17、19、30 秒四个验证点。

如蒙版点位或素材 id 不足，停止并请求所缺对象，不要猜测。
```

## 3. 粗糙波普拼贴：多图素材 → 风格化循环

### 能力边界

此案例的难点不是绘制，而是**素材选择、层次、统一风格和版权边界**。当前浏览器版尚没有面向 Agent 的“读取任意本地素材并自动写回资产库”工具；因此必须先由用户在编辑器中导入素材，或由外部流程提供有 `id`、尺寸、角色、版权状态的 Asset Manifest。没有资产清单时，Agent 只能做规划，不能输出可运行图片 Scene。

### 规划提示词

```text
用户提供若干图片素材与文字主题。先输出拼贴方案，不输出 JS。

主题：把“城市夜游”做成带立体主义倾向的粗糙波普循环海报。
素材清单：每张素材将给出 id、缩略图、尺寸、主体、是否可裁切。

请：
1. 从素材中挑选 3–7 个，说明舍弃其余素材的理由；
2. 定义前中后景、主要视觉重心和两处故意保留的切口/错位；
3. 指定每个素材的裁切、旋转、描边、阴影、纹理或局部 FX；
4. 只规划 2–4 个循环运动（如招牌闪烁、纸片轻摆、颗粒漂浮）；
5. 写出一个色板与“禁止事项”：不要把所有图片同时加满效果，不要用真实模糊掩盖层级问题。
```

### 生成/修正提示词

```text
已导入以下素材：{Asset Manifest：id、w/h、语义、可裁切范围}。
依据确认后的拼贴方案，为现有 GENERIC_SCENE 输出最小 Scene Patch。

要求：保留素材 id；按方案创建/调整图片图层、组、硬边描边和阴影；纹理只用于明确的填充区域；不新增外部资源；元素均有稳定 id；局部 FX 仅绑定指定元素且不越过其蒙版。循环 12 秒，固定验证点 t=0/4/8 秒。

先输出变更对象列表和层级顺序；再输出 Patch；最后列出用户可在 Inspector 中继续调整的参数。
```

## 4. 视觉审稿提示词

所有案例共用，不让审稿 Agent 直接重写 Scene：

```text
你是 Patcharium 的视觉审稿 Agent。比较参考输入与 t={...} 的 Scene 渲染帧。
只输出：构图、层次、色板、运动节奏、编辑性五项中的问题；每项定位到稳定 id；按“必须修 / 可选修 / 不应修”分类。禁止生成 JS，禁止要求把高细节底图强拆成图元。
```

## 5. 提示词失败的处理

- Agent 编造图片、data URL 或素材路径：拒绝 Scene 生成，退回素材清单阶段。
- Agent 用大量 parts 模拟高密度静态纹理：要求改做底图/语义图片层，或明确接受低保真图元风格。
- Agent 输出整份 Scene 来修改一个对象：要求重发最小 Patch。
- 合同校验失败：先修结构错误，再进入视觉审稿；不要让视觉讨论掩盖无效数据。
- 视觉不成立但结构合法：保留 Scene，进入审稿 → Patch 迭代；不要因此放宽合同。
