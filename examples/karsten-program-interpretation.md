# 案例 02：单图参考 → 自生成气象小景

## 参考的使用方式

输入仍是 `assets/karsten.jpg`，但成品**不显示原照片**。Agent 只借用其竖幅镜头、山脊高度、孤立人物尺度、阴云和冷暖关系，重组为“山脊旅人 · 气象观测站”。这验证的不是照片局部动起来，而是参考图是否能转化为一套自洽、可运行的场景规则。

## 程序元素层

| 程序元素 | 可公开调整 | 动态 |
|---|---|---|
| 气象天空 | 云速、暮色、颗粒 | 双层云群匀速经过、像素颗粒 |
| 远山地貌 | 空气透视、积雪高光 | 静态地貌承担结构与细节 |
| 山脊观测站与旅人 | 信号灯、围巾风力 | 灯光呼吸、围巾摆动、风中微粒 |
| 前景风痕 | 风痕强度 | 连续风线穿过前景 |

每项都是 `program.code` 黑盒，但均有稳定 id、可选择边界、`params`、Inspector 暴露项和标准 `show / alpha / rot / mask / FX` 外壳。用户可在其上方继续添加普通图片、图元、粒子或局部效果作“创可贴”覆盖，而不需要拆开树林、山体或人物的所有内部像素。

## 验收点

| 时间 | 预期 |
|---|---|
| 0s | 冷暮色天空、层叠山脊、旅人与观测站构成稳定画面 |
| 8s | 云群、灯光、围巾与风痕均处于不同节奏，仍不抢主体 |
| 16s | 调整 Inspector 中公开参数能改变相应构件，不影响其它层 |
| 23s / 0s | 程序时间函数以 24 秒循环，无明显断裂 |

## 当前限制

`program.code` 是本地受信任 Scene 的扩展能力，不是安全沙箱，也不会自动把内部细节变成可编辑 parts。它的合同是“黑盒绘制 + 白盒外壳”；后续需要补充程序元素的覆盖附件/锚点，才能让创可贴层在其内部自定义锚点上自动跟随。
